# Conveyor handling line usability review

TCAD can build and reuse a substantial assembly from sketches, but the interaction cost rises sharply as parts and patterns accumulate. The largest problems are editor responsiveness, ambiguous selection scope, a flattened assembly tree, and a property manager that gives status and explanation more space than the active task. Making the buttons smaller alone will not resolve these problems.

This review covers the UI session of October 12–13, 2026, using the desktop build associated with `5561019` and the existing personal theme. It produced a three-module conveyor concept with 102 active part occurrences. The concept is useful for further UI work, but its engineering detail and drawing package remain incomplete.

## Priority one findings

### Editor responsiveness needs bounded work

**P1-01 — Chamfer editing became inaccessible.** In Part5, opening Chamfer with a 2 mm equal-distance value and attempting to pick the central bore rim led to repeated computer-control timeouts. The TCAD process remained alive. A three-second process sample placed the main thread in `property_manager → feature_editor → semantic_field → current_value → live_element → semantics`, with provenance encoding below that path. Recovery required force-quitting TCAD and reopening the saved module. No chamfer geometry was committed or verified.

Cache the operation's semantic controls and topology choices by document/draft/evaluation revision. Reading each displayed value should not regenerate the complete semantic editor or serialize provenance again. Revalidate an action against the current revision when it is dispatched. Keep cancel and navigation responsive even when selection data is expensive.

**P1-02 — The larger assembly drawing could not be completed.** Drawing → New Sheet on the three-module line was followed by an inaccessible window, repeated reconnect timeouts, and a TCAD memory reading of about 4.3 GB. A process sample showed substantial main-thread work in `drawing_interaction_ui::frame`, `draw_primitive`, `drawing::display_curve`, and painting. The source assembly had already been saved, but a drawing was not saved or exported.

Cache projected display curves and reusable drawing primitives. Bound tessellation and painting work, cull outside the sheet/viewport, and move expensive projection work behind a cancellable evaluation contract. Source geometry and output quality must remain authoritative; display caches should be disposable. The sample identifies an investigation target, not a proven single cause of the failure.

### Selection and assembly scope need to be explicit

**P1-03 — Editing a part and selecting a component mean different things without clear feedback.** Clicking a component in the root tree enters its definition, but root Move and Component Pattern can still use an earlier geometry selection. After working on the guard or mount, a new pattern initially selected the roller. The per-occurrence Move command in Components targeted the intended part successfully, but finding it required expanding and scrolling a long manager.

Give a normal component click a visible selection state. Expose Move, Rotate, Ground and Edit from that selected occurrence. Enter definition editing through an explicit action or familiar double-click. Show the primary occurrence, parent assembly and editing scope at the top of every assembly operation. A new pattern should visibly confirm its seed selection before showing copies.

**P1-04 — Ghosted context competes with the active part for picks.** While working on the mount, an edge click selected the guard, and a face click selected the structural frame. Candidate cycling eventually reached the mount face, which appeared as candidate 4 of 6. Tab also advanced toolbar focus while cycling candidates.

Prioritize active-part geometry. Provide an explicit context-reference mode for picking other components, and a separate deliberate gesture for cycling overlapping candidates. A candidate list should show part, occurrence, entity type and a small preview. Candidate cycling must not also move keyboard focus. The assembly display-state text says ghost components are ignored by viewport picking, so the behavior of editing-context ghosts and display-state ghosts needs one clear rule.

**P1-05 — The model tree loses the assembly's structure.** The line's underlying source correctly contains three occurrences of one subassembly. The visible tree instead exposes repeated child names such as Part3 and Part5 without a useful module boundary. Inside a module, copies appear in an order such as 4, 2, seed, 12; nested leg patterns also produce duplicate visible names. Collapsing Components helps reach the task controls but removes useful navigation.

Use a hierarchical, virtualized occurrence tree. Start with the three modules collapsed; group pattern copies under their pattern, use natural ordering, and retain meaningful occurrence paths. Add search, filter, breadcrumbs and rename-in-place. Distinguish a shared definition from an occurrence. Do not change stable IDs to improve labels.

### The property manager should prioritize the active task

**P1-06 — Task controls are buried under repeated information.** Feature history, Pending Changes, duplicated feature/part titles, multiple confirmation areas, long help paragraphs and selection lists precede the useful inputs. Four structural path rows alone occupy a large portion of the rail. A component pattern lists every eligible occurrence before its spacing fields.

Keep one compact operation header and one sticky confirmation group. Put selection summaries and primary parameters immediately below them. Move history to its own tab or collapsible region during an operation. Show a compact list of selected references, with viewport selection and searchable expansion for the full candidate list. Collapse detailed help and technical diagnostics by default. The design should make the next required action visible without scrolling.

## Linear pattern direction behavior

The user's requirement applies to part and assembly patterns. A picked straight sketch member, reference axis or straight component edge should define an associative direction in the pattern owner's coordinates. For an assembly edge, preserve the occurrence path and transform its direction from the component's local coordinates. Direction changes should follow the referenced geometry after editing or moving the source component.

Show the picked reference by name, a reversible arrow, spacing and instance count. Offer a second direction for a grid rather than requiring nested patterns. Reject unsuitable curved edges with a useful explanation unless the user deliberately selects a tangent-based mode. Retain coordinate/vector entry under an optional advanced control. This requirement is recorded here; it is not implemented by this review session.

## Compact and fully styleable presentation

| Region | Default content |
| --- | --- |
| Scope row | Document → assembly occurrence → part, with one selected-item summary. |
| Model tab | Hierarchical feature/component tree, search/filter, compact badges and natural order. |
| Operation tab | Operation name, validation state, selection targets, primary parameters. |
| Sticky action row | OK/Apply and Cancel, sized to fit their labels. |
| Optional expansion | History, secondary parameters, instructions, technical diagnostics and Advanced Source. |

Expose these as semantic regions and controls through the existing presentation contracts. Themes should be able to relocate them, choose density, change order, style selected/disabled/error states and replace the default arrangement. Stable semantic identity, keyboard behavior and accessible labels should survive a theme change. Avoid hard-coding a particular year's command list or a fixed feature-specific panel layout.

The current personal theme was retained throughout the session. Its clipped labels and faint controls should not be treated as proof that every newly bundled theme has those same defaults. Existing saved themes still need a useful preview, content-fitting defaults and optional migration assistance without silently rewriting the user's customization.

## Successful workflows and unfinished engineering

The usable foundation includes sketch-first modeling, multiple closed contours, library structural profiles, mitered frame members, nested profile holes, component placement, repeated components, linked subassembly insertion, formed sheet-metal returns, a flat-pattern DXF, validated drafts and cancellation. These workflows produced actual saved geometry.

The review concept still needs rear bearing supports, the remaining shafts and end inserts, guard penetrations and fasteners, bracing/feet, module transfer details, welded connections, material assignments, mating constraints, fit/tolerance decisions and production drawings. The source still uses the default Aluminum material. Only one shaft per module is present, and the assembly uses placement seeds and patterns rather than a completed mate network. These are unfinished design tasks, not evidence that the corresponding software capability is missing.

No weld bead, native BOM CSV, cut-list CSV or drawing PDF/DXF was completed in this session. The large drawing attempt blocked further interaction; the subsequent source reopen succeeded, but desktop control became inaccessible again before export. The files contain zero committed drawing sheets. These outputs must remain outstanding rather than being described as successful.

## Recommended implementation order

1. Bound semantic-editor work and drawing display work. Use the mount and three-module source as concrete reproduction inputs. Keep cancel/navigation independent of expensive geometry and projection work.
2. Make occurrence selection, editing scope and ghost-reference selection explicit. Isolate candidate cycling from keyboard traversal.
3. Restore hierarchical assembly navigation and group patterned occurrences. Add search and meaningful labels.
4. Restructure the rail around the active operation, with stable input placement, compact selected-reference lists and one confirmation group. Keep the semantic regions theme-controlled.
5. Add associative direction picking and a second linear-pattern direction. Use frame edges and roller axes as the natural design inputs.
6. Resolve the counterbore's coincident-boundary kernel case, then resume edge finishing and the unfinished fabrication/drawing detail.

## Evidence limits

This was UI authoring for the user's requested dogfooding exercise. No application code was changed, and no code tests, compilation or linting were run for these model/document artifacts. Saved source files were read afterward to confirm definitions, pattern parameters and quantities.

Computer-control round-trip durations are not CAD evaluation benchmarks. Where visible, native geometry evaluation generally reported hundreds of milliseconds to about 2.1 seconds. Reconnect timeouts, input replacement failures, occasional stale accessibility IDs and native-dialog shortcut difficulties are qualified as automation behavior. The two inaccessible editors warrant investigation, supported by process samples, but neither is presented as a proven native crash. Recovery used saved checkpoints, and TCAD was finally reopened to a responsive empty workspace.

Only compact definitions and this report are included in the repository. The two process samples were temporary diagnostic captures, not per-part application logs or model geometry caches.
