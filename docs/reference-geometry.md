# Parametric reference geometry

Reference definitions are saved as feature operations. Their expression text, construction modes, feature/member references, and identities are authoritative. Evaluated planes, axes, points, and coordinate systems use the application-owned `reference_geometry` contract, version 5, with f64 coordinates in millimeters and normalized directions. They do not store renderer or kernel objects. Coordinate-system source definitions use their own version 1 contract.

The default Reference group offers Plane, Axis, Point, and Coordinate System. Each uses the common docked feature editor, persistent worker preview, current-result validation, checkpoint Cancel, and single-operation undo. A datum leaves body outputs in place. Distances accept explicit units and named parameter expressions; angles accept degrees or radians. Invalid or ambiguous references fail the draft without changing the committed definition.

| Feature | Implemented definition modes |
| --- | --- |
| Plane | Signed offset/on planar face with optional flipped normal; rotation of a plane about an axis; three noncollinear points; midway between distinct parallel planes; through a point normal to an axis; either angular bisector of two intersecting planes with normal reversal; tangent to a proven bounded native face at normalized parameters or a supported associative point anchor. |
| Axis | Two distinct points; intersection of two nonparallel planes; through a point normal to a plane; an exact straight body/surface edge, sketch line/centerline, or existing axis; cylinder/cone face axis; circular model edge or solved sketch circle/arc; point plus three scalar direction expressions. |
| Point | Three coordinate expressions, an existing datum point, solved sketch point, plane/axis construction origin, or normalized model-edge parameter; signed distance along an axis; plane U/V coordinates and normal offset; axis/plane intersection. |
| Coordinate System | Associative point/coordinate origin plus two directions from axes, supported edges/rotational faces/sketch lines, plane normals, two-point vectors, or three scalar expressions. Choose any two distinct output axes and reverse either driving direction. |

Coordinate systems preserve the primary unit direction, project the secondary direction perpendicular to it, and derive the third axis with right-handed orientation. Coincident points, zero/nonfinite directions, repeated output axes, and parallel or nearly parallel directions fail explicitly. Evaluated source frames are validated again at their consumers: nonfinite, nonorthonormal, or left-handed frames are rejected. These features do not introduce scale or skew. Each evaluated frame publishes its origin, three axes, and XY/XZ/YZ planes as independent semantic construction elements with stable roles. The viewport draws and picks this triad and its planes; optional `--coordinate-x`, `--coordinate-y`, and `--coordinate-z` theme variables color the directions.

The reference selectors expose every coordinate-system axis, plane, and origin. A selected coordinate plane can host an associative sketch; selecting the coordinate-system feature in the tree while assigning a sketch plane chooses XY. Plane picking and Normal To follow the exact selected component occurrence path. Revolve/Pattern axes and Mirror/Draft planes use the same selectors. Assembly source choices include each element and the complete frame with Z as its primary direction and X as its transverse direction; the complete frame retains twist orientation for rotation-locking and angular relationships. Configuration/suppression and feature dependency ordering apply to all frame consumers. No renderer coordinates or kernel IDs are saved as their source identity.

Plane references can use Front, Top, Right, an earlier datum plane, or a planar body/surface face. Axis references can use X/Y/Z, an earlier datum axis, an exact straight edge, an earlier sketch line, a supported rotational face, or a circular model/sketch member. Point references can use datum points, saved sketch point IDs, or plane/axis origins. Dependencies participate in the same graph as modeling features; missing, suppressed, cyclic, degenerate, or ambiguous sources are reported.

Angular Bisector retains two plane sources and a choice between equal signed distances and opposite signed distances. These produce the two perpendicular bisector planes through the original planes' intersection line. Each source's authored normal determines its signed distance. Reversing the result changes its normal while preserving its location. Parallel/coincident references and intersections too ill-conditioned for native precision are rejected. Intersection coordinates are calculated relative to the first source origin to reduce cancellation at distant document coordinates.

Tangent to Face saves the current owning body, the selected face's construction reference, an anchor definition, and optional normal reversal. Choosing Plane with a selected curved model face starts this mode; the docked Plane Definition selector also exposes it when a source face is selected. Normalized Face Parameters accepts scalar U/V expressions in 0..1 over the proven selected domain, rather than a fraction of arc length. Associative Point uses the shared point selector, including sketch/datum points and native model-edge parameters. The native worker resolves the face again for each edit, verifies its bounded domain, and evaluates the actual surface anchor and derivatives. The resulting plane uses the selected face orientation before optional reversal. It can host sketches and drive existing plane consumers. Source, anchor quantities, solution choices, and reversal publish separate semantic fields with stable feature targets.

Tangent face domains currently supported are:

- Full clamped polynomial/rational B-spline patches with finite positive homogeneous controls, at most 1024 controls, one boundary wire, and four boundaries proven to be the complete natural carrier domain. These use the native knot-domain U/V coordinates. Normalized parameter anchors are supported wherever both native derivatives give a finite regular tangent. Associative point anchors additionally require a proven cylindrical/conical ruled carrier and strictly monotonic bounded circular sections; the native inverse must converge inside the domain with a carrier residual at most 1e-7 mm. General rational patches use parameter anchors because a unique inverse has not yet been proven.
- Rectangular planar faces with four exact bounded straight edges and a nondegenerate orthogonal rectangle. Their normalized domain follows the selected face's native boundary traversal, using the first corner and its adjacent edges. Both anchor modes verify containment in the rectangle and evaluate the native plane.
- Native line-generated revolution faces proving a regular cylinder or conical frustum, finite invertible affine transforms preserving rotational form, and one four-edge boundary consisting of two straight generators and two exact monotonic circular arcs. The boundaries must prove a common bounded axial/angular rectangle with an angular extent below one turn. The native processor's U/V orientation is retained. Both parameter and associative point anchors are supported; point anchors must resolve uniquely inside that axial/angular domain and match the actual carrier within 1e-7 mm.

Tangent definitions reject holes, general pre-existing trims, implicit/intersection or unproven parameter-curve boundaries, collapsed apex sections, closed periodic seam domains, nonlinear revolution generators, singular/ill-conditioned derivative locations, and failed/outside inverse anchors. Exact rational boundary equality or complete bounded line/circle proofs establish the supported domains; display meshes, guide polylines, and sampled containment are not authority. Broader trims and carriers remain engineering work in scope.

Model-edge point sources save the current owning body, construction `TopologyRef`, and a scalar parameter expression in 0..1. The selected edge's stored native curve orientation defines Start (0), Parameter midpoint (0.5), and End (1), independently of the first incident face's traversal. The adapter evaluates the actual bounded native curve, including supported polynomial/rational, parameter-space and intersection carriers; it does not interpolate a displayed mesh or guide polyline. Implicit intersection evaluation must converge on both supporting surfaces with finite parameters and native-precision residuals; projection failure rejects the draft instead of substituting its guide. Endpoints retain the actual construction vertices after carrier consistency checks. A finite nonzero native interval, finite endpoint/point evaluation, consistent constructor endpoints and unambiguous construction provenance are required. Midpoint denotes native parameter midpoint, not half the arc length. Missing provenance and topology-changing ambiguities require explicit replacement.

Click a model edge and choose Reference Point on Edge, or choose the selected edge in any docked point-source selector. Start/midpoint/end controls and an expression field share the live draft and validation path. These sources also drive plane/axis point constructions, coordinate-system origins/directions, scale/mold centers and assembly point frames. The mate selector offers the selected occurrence's edge start/midpoint/end, retains the complete occurrence path, and reuses the same source/parameter fields. Layout-independent semantic source and scalar quantity elements publish the owning body, construction reference, parameter bounds and parameterization for both features and mates. NodeRefs, TopologyRefs and expressions use the existing native library/Make Unique traversal.

Evaluations publish reference descriptors for both base parts and placed configurations. The model viewport displays and picks datum bounds, axes, points, and labels, with history-prefix filtering. Display extent is a view property and does not bound the mathematical reference. The `reference-geometry` semantic role and plane/axis/point classes receive user-defined theme properties; changing appearance does not alter engineering definitions.

A saved plane can host a sketch in the same model viewport. Its source reference is retained and the plane is resolved again when the datum changes. Pick a datum plane on the model or choose it in the tree while assigning the sketch plane. Plane actions include Sketch on Plane and Normal To. References and downstream commands also publish layout-independent semantic descriptions.

Revolve and circular body pattern can retain an axis reference, including a sketch construction line. Pattern rotation uses the axis construction origin. Mirror and Draft can retain a plane or planar face reference. These references resolve on every evaluated edit and remain saved when dimensions change. Existing documents retain their numeric axis/plane fallback; the editor offers an explicit associative-reference toggle. Revolve uses a single construction line in its selected sketch by default when that choice is unambiguous.

Face-axis sources support native revolution surfaces whose finite invertible affine transform preserves equal radial scaling, perpendicular radial directions, and axis orthogonality. Positive-weight rational ruled faces also support cylinders and conical frustums when the linear ruling direction, two exact circular sections, and proportional radial controls/weights prove the rotational carrier. Collapsed apex sections, nonlinear or elevated ruling parameterizations, sheared/elliptical carriers, and implicit extrusion guides are rejected. Circular model edges require exact degree-2–32 Bernstein circle identities; short or ill-conditioned arcs are rejected. Sketch axes support actual circle/circular-arc members and legacy circles on the current solved associative sketch plane. Exact straight-edge sources prove collinearity of positive rational controls. No carrier is fitted from tessellation; missing or ambiguous construction provenance fails explicitly.

Unsupported reference modes remain work in scope: tangent planes on the broader trimmed/implicit/periodic domains described above, independent B-rep vertex and arc-length curve-point modes, projected reference curves, bounding boxes, and centers of mass. Reusable composite curves, curve-through-points, and analytic helices/spirals have their own [reference-curve contract and native applicability limits](reference-curves.md). Coordinate systems consume the origin/reference-point sources listed above; automatic center-of-mass origins remain unimplemented. Endpoint sources use the selected edge's constructor rather than an independent persistent vertex identity. These operations do not synthesize substitute geometry. Compilation and linting are engineering checks; interactive acceptance remains with the user. No code tests or interactive smoke tests were added or run.
