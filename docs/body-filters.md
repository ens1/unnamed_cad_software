# Keep and Delete Bodies

Keep Bodies and Delete Bodies filter whole native solids in one or more earlier solid-producing feature outputs. Select a face on a solid in the active part and choose the command. The docked editor saves the owning source output and that face's exact construction reference. Add other source outputs to the scope and pick faces on their solids to include more selections. Several picked faces on the same solid count as one selected body.

Keep Selected retains the selected solids and removes every unselected solid within the saved scope. Delete Selected removes the selected solids and retains the unselected solids within that scope. Other document outputs remain outside the feature's scope. Deleting every scoped solid is a valid empty output. These operations perform no geometric splitting, trimming, healing or tessellation-based body detection: surviving solids are cloned unchanged with every native face and edge retaining its source ancestry.

The application-owned body-filter contract version 1 stores ordered scope feature references, face anchors with their owning outputs, and the Keep/Delete mode. It stores no native solid index or center/size-based selector. Evaluation resolves each anchor within its owning output using its exact producer and construction role. If the anchor no longer identifies a solid, or identifies multiple solids, evaluation fails with an explicit reselection message. Two different face anchors on the same owning native solid are deduplicated only during evaluation; all authored anchors remain editable source intent. Advisory geometric signatures are ignored for selection and newly picked anchors omit them.

The feature consumes its scoped output branches and produces their surviving solids as an editable feature output. Source edits and configuration changes reevaluate its anchors; suppression passes the scoped outputs through. Library imports remap feature and nested construction references through the normal source identity mapping. Editing a pinned library definition requires making it unique, and editing a component requires entering that component's part context. The property manager, semantic presentation fields, worker validation, Apply/Cancel checkpoint and document undo all use the shared feature editing path. Apply requires the current validated evaluation and commits one undoable operation; Cancel restores the initial source and output branches.

Scope contains 1–256 unique solid-producing feature outputs, with 1–4096 saved face anchors. Any already supported closed native solid can be filtered, including curved, concave, pocketed and multishell solids; no new carrier reconstruction is required. Surface bodies, sketch profiles and reusable reference curves are excluded. Missing source ancestry, conflicting ancestry on shared topology and ambiguous anchors are rejected. Scoped outputs that alias the same exact native solid are also rejected before filtering, so repeated source branches cannot duplicate a surviving solid. This uses transient complete face/orientation correspondence rather than saved native IDs or signatures. A repeated source whose identical face ancestry identifies several solids needs a distinct construction face before it can be selected. Automatic geometric fallback, changing a filter into a split/delete-face operation, selecting bodies by array position, and cross-component editing without entering the part context are unsupported.

The desktop selection workflow starts from one explicit model face. Additional scopes and anchors remain editable in the docked property manager; changing or removing a scope is part of the same draft, and removing it also removes its saved anchors. Interactive acceptance remains for the user. No tests, probes or manual UI exercises were run for this feature.
