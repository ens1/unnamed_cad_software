# Native selected contours

Extrude, Revolve, Loft and Sweep share the application-owned `tcad.contours` version 2 selection contract. `options.contours` is an ordered list of `{ profile, outer_members }` records. `profile` is the source `NodeRef`; `outer_members` retains its historical JSON field name and contains persistent native material member IDs identifying one or more regions. Version 1 documents remain readable. An omitted or empty list keeps all closed material regions; disconnected open chains do not invalidate those regions. For Loft, a profile with no records keeps its all-region behavior.

The docked Selected Contours group provides a compact scrollable contour checklist, selection ordering and All Closed Contours. Select All records stable anchors for all eligible groups; clearing an explicit selection requires new picks before Apply instead of silently reverting to all regions. Command/Shift member selections in the sketch are carried into section-based feature creation. Source data and complete IDs remain under Advanced Source. Semantic contour actions and styled controls use the same feature draft, current-validation Apply, Cancel and undo as the other fields.

Selections resolve against the current solved sketch and exact traced section boundaries, before the solid is built. Each member must resolve to exactly one closed material region. The entire region is retained, including its contained holes. Picking an inner-hole boundary selects its containing material region with the hole intact. A multi-member record can select several regions, and duplicate picks contribute each region once. Deleted, suppressed, construction, nonnative, off-profile, open or ambiguous member ancestry produces an explicit diagnostic; a region is never substituted by area or position. Legacy profiles without native member identities remain readable with All Closed Contours.

Selected regions keep their first occurrence in record/member order within each profile. Loft pairs that order across sections; the Move Up and Move Down controls allow an explicit correspondence. Sources left in All Closed Contours retain descending-area pairing. Native member ancestry continues to name walls, caps and shared edges independently of the selected region's list position.

With Thin Feature enabled, each selected member identifies its connected source chain. Selected chains retain first-pick order and are resolved before offsetting, so unrelated chains are excluded. Straight members, circular arcs and circles retain the existing exact offset modes and flat open ends. Branching or unsupported ellipse/spline offset chains fail explicitly. The offset material region must still resolve uniquely to the selected chain ancestry; uncertain intersections are not accepted.

The application-owned `tcad.sketch_topology` version 1 contract derives section connectivity with a fixed `1e-6 mm` endpoint tolerance. Explicit authored coincidence/contact aliases are retained through effective-curve preparation, before temporary section derivation metadata is flattened. Pattern instances inherit coincident source endpoints when their saved transform, instance index and placement agree, including separately patterned members sharing a source endpoint. Connections propagate through chained patterns and are checked against the complete alias cluster. Isolated mutually unique material endpoints can share a derived section vertex within the same tolerance. Construction geometry, centers and intermediate controls are excluded from this healing; ambiguous near clusters, joins to existing junctions and line interiors are not guessed. Source points, IDs, constraints and saved pattern definitions remain unchanged.

The checklist describes native member connectivity, not a proof of valid area or nesting. Current kernel validation still checks closure, crossing, touching and hole containment. Unrelated branched networks can still prevent native sketch construction; general planar arrangement extraction remains work. Multiple valid regions already construct independent boss tools or sequential cut tools, including Through All and Through All Both, over every scoped output body.

Loft connectors now have an optional `region_member` native outer-boundary anchor. New connectors use it, and the kernel resolves it against the current selected sections. `vertex` still identifies the actual seam vertex, and `contour` selects the outside (0) or a contained hole in canonical source-member order. Older connectors with no `region_member` keep their explicit legacy `region` index. The editor labels that compatibility mode. It cannot be combined with Selected Contours on the same profile until the user chooses a native region anchor; no ordinal record is silently migrated.

Extrusion starts can additionally use `Start::Point { point }`, where `point` is a boxed application-owned `PointSource`. Coordinates, datum points, coordinate-system origins, sketch points, plane/axis origins and native model-edge parameter points are associative sources. The section is translated along the extrusion axis to the source-parallel plane passing through the resolved point, then by Start Offset. Edge parameters use the constructor-oriented native curve parameter in 0–1, including the exact endpoints, rather than an arc-length percentage. Current reference validation remains required before Apply.

Contour selection does not broaden the underlying feature's carrier or Boolean domains. The extrusion termination bounds, nonfolding parallel-section loft proofs, sweep path/frame proofs and revolution axis-contact bounds remain documented in the respective feature contracts. Geometry is evaluated as exact B-rep data; UI preview tessellation is derived display data.
