# Native selected contours

Extrude, Revolve, Loft and Sweep share the application-owned `tcad.contours` version 1 selection contract. `options.contours` is an ordered list of `{ profile, outer_members }` records. `profile` is the source `NodeRef`; `outer_members` contains one or more persistent native sketch member IDs on one outer material boundary. An omitted or empty list keeps all material regions. For Loft, a profile with no records keeps its previous all-region behavior.

The docked Selected Contours group adds and removes source-member picks, and can restore All Contours. It names the material members without exposing IDs in normal controls. Source data and complete IDs remain under Advanced Source. These controls edit the existing feature draft, so geometry preview, current-validation Apply, Cancel and undo use the same document workflow as the other feature fields.

Selections resolve against the current solved sketch and exact traced section boundaries, before the solid is built. Each record must resolve to exactly one outer material region. The entire region is retained, including its contained holes. An inner-hole member cannot select a separate filled disk. Deleted, suppressed, construction, nonnative, off-profile or ambiguous member ancestry produces an explicit diagnostic; a region is never substituted by area or position. Legacy profile records without native member identities remain readable with All Contours.

Selected regions keep their record order within each profile. Loft pairs that order across sections; the Move Up and Move Down controls allow an explicit correspondence. Sources left in All Contours retain the older descending-area pairing. A repeated pick of the same material region contributes that region once. Native member ancestry continues to name walls, caps and shared edges independently of the selected region's list position.

With Thin Feature enabled, the same records identify connected source chains. The selected chains are resolved before offsetting, so unrelated chains are excluded from the thin feature. Straight members, circular arcs and circles retain the existing exact offset modes and flat open ends. Branching or unsupported ellipse/spline offset chains fail explicitly. The offset material region must still resolve uniquely to the selected chain ancestry; uncertain intersections are not accepted.

Loft connectors now have an optional `region_member` native outer-boundary anchor. New connectors use it, and the kernel resolves it against the current selected sections. `vertex` still identifies the actual seam vertex, and `contour` selects the outside (0) or a contained hole in canonical source-member order. Older connectors with no `region_member` keep their explicit legacy `region` index. The editor labels that compatibility mode. It cannot be combined with Selected Contours on the same profile until the user chooses a native region anchor; no ordinal record is silently migrated.

Extrusion starts can additionally use `Start::Point { point }`, where `point` is a boxed application-owned `PointSource`. Coordinates, datum points, coordinate-system origins, sketch points, plane/axis origins and native model-edge parameter points are associative sources. The section is translated along the extrusion axis to the source-parallel plane passing through the resolved point, then by Start Offset. Edge parameters use the constructor-oriented native curve parameter in 0–1, including the exact endpoints, rather than an arc-length percentage. Current reference validation remains required before Apply.

Contour selection does not broaden the underlying feature's carrier or Boolean domains. The extrusion termination bounds, nonfolding parallel-section loft proofs, sweep path/frame proofs and revolution axis-contact bounds remain documented in the respective feature contracts. Geometry is evaluated as exact B-rep data; UI preview tessellation is derived display data.
