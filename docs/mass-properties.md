# Cached mass properties and reporting frames

The Mass Properties panel reports cached f64 engineering properties for the whole assembly, the selected component, or the selected native body. Its selected scopes use complete occurrence paths, definition IDs and configuration IDs. A selected face or edge supplies its owning native body. Missing or suppressed selections, missing property entries, incompatible cache versions and duplicate occurrence/body identities produce an error. Assembly totals cannot silently omit a component that lacks cached properties.

Reporting coordinates can be World, a selected component's frame, or an evaluated native coordinate system. Component and datum choices retain their full nested occurrence path and selected configuration, together with the datum's producer feature. Matching uses those source identities; names are presentation labels. Datum geometry comes from the configuration-qualified `Evaluation.references` cache and combines with the occurrence's complete evaluated placement. Switching parts, removing a coordinate system or suppressing its feature does not automatically select World. Choose a new frame explicitly when the saved source is unavailable.

Frames must be finite, right-handed rigid transforms. Each cached body's centroid and centroidal inertia tensor are transformed directly from definition coordinates into reporting coordinates. Component rotations rotate the inertia tensor; aggregation applies the parallel-axis theorem about the combined mass center. Canonical values remain millimetres, square/cubic millimetres, kilograms and kg·m²; the panel formats lengths/areas/volumes using the current display units. It never queries geometry or changes source definitions.

Bounds are conservative enclosures obtained by transforming the eight corners of each cached body AABB. They are labelled conservative in the panel, semantic metadata and JSON. They are not tight native extents after arbitrary rotation. Area and volume derive from evaluated boundary tessellations. Exact B-rep integration and integration error bounds remain unavailable. Assembly totals sum independently owned bodies and deposited weld metal; overlapping occurrences contribute separately. Surface bodies contribute area, and solids lacking complete density-derived properties leave mass/inertia unavailable rather than reporting a partial mass.

Current and last-valid evaluations are labelled explicitly and retain the cached evaluation's complete request identity, including its source fingerprint, revision/generation and draft/edit identity. The report does not replace stale provenance with the current draft's source. Historical inspection uses saved stage body IDs only when their matching cached body properties are available. It rejects missing historical metrics rather than presenting final-model totals at an earlier station. A datum created after the station cannot be used as a historical frame. Assembly weld deposits are excluded explicitly while hidden in history view. Full historical property integration remains a separate cache capability.

Report sources come from complete native session caches. Disposable pose-only viewport previews may temporarily hide dependent weld deposits and cannot establish complete assembly totals. While those changes rebuild, inspection retains an explicitly labelled last-valid native source; the cache key includes native source/completeness stamps as well as the request, so a later complete result replaces any prior incomplete display result.

The default panel keeps mass, area, volume and three bounding sizes visible. Centroids, minimum/maximum bounds and the six independent centroidal inertia entries are compact expandable groups. Scope/frame controls, labels, metric values, error/status messages and export actions have independent semantic IDs and CSS-like styling targets. Custom layouts may bind individual `inspection-metric` entries and `inspection-field` choices through the `inspection-report` value adapter. Metric metadata includes its canonical numeric value/unit, group, reporting frame, history station, cache state and evaluated source. User-defined presentation does not affect engineering aggregation.

Aggregation is cached by evaluation identity, scope, frame and history request and shared between native and portable presentation. Export JSON writes only a complete available report. The version 1 report contains its source-qualified request, rigid frame-to-world matrix, complete contributing body/occurrence list, source/geometry validity, bounds/inertia basis, canonical metrics and limitations. A bounded writer rejects output above 16 MiB before a file is written, with at most 100000 contributing bodies and 64 path levels. Saving uses the existing atomic local-file writer. The same core `inspection::report::evaluate` API accepts an existing `Evaluation` for future command-line/report consumers without a kernel query.

Implementation verification uses compilation, formatting and strict linting. No tests, probes, interactive smoke runs or application launches were performed; interactive acceptance remains with the user.
