# Fabrication source selection and labels

Fabrication feature creation prefers the currently selected compatible sketch, then the newest suitable sketch. A closed section is checked with the shared sketch connectivity contract, including construction/suppression filtering and authored endpoint connections; an open or branched material chain does not qualify merely because the same sketch also contains a circle. Native geometry evaluation still establishes nonintersection, area, and nesting.

Structural member groups distinguish a selected open path or previously used path from a selected closed section. For the first group, a selected newest closed path following another suitable section follows section-then-path creation order. Subsequent groups prefer the selected/newest compatible section, rather than silently reverting to Sketch1. Closed sketches can be compatible with both roles; their explicit section and path selectors remain the authority for resolving that intent. Compatible choices are filtered, and an existing incompatible authored choice is displayed rather than silently replaced. Synthesized legacy profile members are added only when native members are absent.

Sheet attachments use explicit tree/model selection as flange-chain intent. A model carrier's authored member ancestry identifies its originating strip; its latest feature owner alone does not. A stale active feature after commit no longer implies a terminal attachment. Without an explicit selection, an available base edge is preferred, followed by an available flange terminal. Existing authored attachment choices are retained while their fields are edited.

Cut-list rows retain their original `section` NodeRef and source-member lineage. They additionally expose optional `SourceLabel` metadata with display contract version 1, a `Part / Sketch` name, and an imported library name when present. Labels come from the current document, separately from geometry and grouping identity. Older row metadata without a label remains readable and is refreshed during grouping. Unsupported label versions are not interpreted as current names.

Production panels, configurable CSVs, and drawing tables share this section display contract. The evaluated CSV uses readable text in Section and appends Section source for the stable source reference. Configurable Source/Definition columns and row semantic data continue to expose source identities. Names and label metadata do not change stock equivalence, manufacturing quantities, item reservations, or saved source keys. Renaming a sketch or library therefore changes its displayed label without changing its manufacturing identity.

Compilation, formatting, and linting are the available implementation checks. No code tests, probes, or interactive acceptance exercises were performed for these changes.
