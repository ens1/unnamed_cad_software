# Native format, version 1

`project.json` contains `schema_version`, the document header, and stable-ID-to-relative-file maps named `parts` and `assemblies`. The document header contains the root definition ID, name, revision, materials, imported resources, drawing sheets, review comments, component-library pins, and custom properties. Part and assembly definitions live in their own JSON files. The Rust types in `crates/cad-core/src/document.rs` are the normative schema; all serialized enum tags use snake case.

A part contains `id`, `name`, `parameters`, `features`, designated solid/surface `outputs`, `material`, `properties`, `sketches`, and `configurations`. Features contain a stable `id`, name, suppression state, and tagged `operation`. References are `{ "definition": "part-id", "node": "feature-id" }`. Dependencies determine evaluation order; vector order is the feature-history presentation, not an implicit geometric dependency. A part may have multiple independent solid and surface outputs. A profile or reference node can be an input without being a manufactured output.

Sketches store plane-local f64 points, constraints, and a stable-ID `members` map. Each member has `construction` and a tagged `curve`: `line` (start/end point IDs), `arc` (start/through/end IDs), `bezier` (2–16 control-point IDs), `nurbs` (control-point IDs, positive weights, clamped knot vector and degree), `circle` (center ID/radius expression), or `ellipse` (center ID/major/minor/angle expressions). Rectangles, polygons and slots are compositions of these members. Multiple closed contours form islands or nested holes; open contours can define paths. Legacy segments, ordered polygon contours and `circles` remain readable; the desktop converts edited legacy sketches to members. A profile feature owns the sketch plane. A planar face reference may also carry `reference_body`, identifying the body in which the inherited construction face is resolved. Sketch drawing is projected onto that plane in the shared model viewport; screen coordinates never become authoritative geometry.

Sketch editing intent v1 adds optional stable-ID maps `conversions`, `offsets`, and `fillets`; absent maps default to empty, so existing schema-version-1 documents remain readable. A conversion is keyed by its generated member and stores the owning source `body`, edge `reference`, exact projected `curve` snapshot and generated control point IDs. The snapshot is a recoverable initial value; worker evaluation resolves the actual source edge each rebuild, and the body is an explicit feature dependency. Detaching removes the binding while retaining geometry. An offset stores `distance`, `reverse`, `closed`, and ordered source/output members with output point IDs and source orientations. A fillet stores its two straight members, virtual sharp `corner`, endpoint orientation flags, `radius`, two trim point IDs, through point and generated arc ID. Output controls are derived from source geometry/expressions, excluded from solver unknowns, and cannot be independently dragged. Generated members keep their own construction flags. Deletion cascades through dependent editing operations; removing a fillet restores its sharp endpoints. Offset distance and fillet radius expressions use length units and can reference named parameters.

Sketch editing intent v2 adds optional `chamfers` and `transforms` maps, retaining schema version 1 and empty defaults for older documents. Chamfers store straight source members, a virtual corner, endpoint orientations, trim point IDs, an output line ID, and equal-distance, two-distance, or distance/angle expressions. Transform records store source member IDs, stable per-instance source/output point and member maps, and mirror, linear-pattern, circular-pattern, or copy intent. Mirrors use a sketch axis or source straight member; circular/copy centers use Origin, a referenced point, or coordinate expressions. Copies support translation, rotation, and positive uniform scaling. Length/angle expressions use the normal unit evaluator. Derived output controls retain sharing within each instance and are excluded from independent dragging. Direct move/rotate/scale instead modify source geometry and retain existing constraints. Pattern count changes retain surviving instance IDs. Detach preserves evaluated geometry and removes its source relation. Generated-operation dependencies are ordered and cycles fail explicitly.

Sketch transformation contract v2 adds optional instance `suppressed` and `placement` fields plus mirror `dynamic`, `dynamic_excluded`, and `dynamic_construction` intent. Default fields are omitted so existing source hashes remain unchanged. Suppressed generated instances retain source/output identities and definitions but contribute no profile members, handles, or active constraint equations; restoration evaluates the same IDs. Additional placement composes exact translation, rotation, and positive uniform scale with the base transform about Origin, an independent source point, or explicit coordinates. Dynamic authoring enrols new non-transform members in the shared draft, retains earlier instance mappings, and excludes existing unselected members and the mirror axis. Stop Dynamic Mirror retains a static association; an empty association is removed. Deleting an enrolled source removes its paired outputs while retaining other enrolled members. Detach materializes active instances and removes suppressed geometry with its obsolete relations. Source topology changes retain surviving generated controls; a retired control with dependent references requires repair or detachment.

Dynamic authoring snaps to instance controls through independent source points and explicit coincidence relations, preserving exact shared endpoint identity without making the new curve depend on its own mirrored controls. A dynamic operation may start with no source members and remains editable through its saved operation ID. Mirror-derived dependent editing operations that would feed back into their own mirror require detachment or a different dependency order; cyclic definitions fail explicitly. Individual instance controls support suppression and additional affine placement, while the original source instance remains ordinary source geometry. Counts support 2–256 instances with at most 4096 source-member/instance entries. Display reflection is disposable preview data; saved members are exact derived curves.

Stretch is an explicit source-control translation edit with retained point/member IDs and active relations. Replace Entities uses an existing exact member as the replacement carrier while retaining the target member ID and, for compatible control topology, its original controls; open/control curves may retain their endpoints across control-count changes. Circle/ellipse replacement retains the original center. Consuming a replacement retains its referenced source points through explicit coincidence relations. Incompatible member relations or lost control references require explicit removal; other relations remain active and may prevent the proposed replacement. Replacing operation-driven curves, changing a patterned source's control count, or exchanging a centered closed curve with an open/control curve requires detachment or a different source edit. Both tools use the normal current-evaluation Apply/Cancel transaction and do not introduce sampled authoritative curves.

Sketch editing intent v4 extends corner fillets to joined line/arc and arc/arc pairs. The legacy `lines` field retains its serialized name. Optional `source_curves` stores original circular source topology; `arc_through` maps each trimmed source arc to a stable generated midpoint handle. Empty maps are omitted for backward-compatible source hashes. Exact offset-carrier intersections produce bounded, orientation-consistent tangent fillets; original point IDs and circular carriers remain authoritative. One corner fillet per source arc is supported. Removing the modifier restores the original arc rather than reconstructing it from display samples. Independent rational offsets preserve control topology, degree, knots and weights for algebraically proven circular or straight carriers, and degree-one polylines use exact line intersections for mitered joins. General ellipse/spline parallel offsets are rejected instead of sampled into replacement curves.

Sketch constraints additionally support optional `driven` (false by default and omitted when false) and `contact` (absent by default). A driven dimension measures solved exact geometry, publishes a separate evaluated value and introduces no solver equations or handle locks. Its authored `value` expression remains saved so switching back to driving restores the original intent. Contact intent stores two normalized curve parameters and flags indicating which may slide during the solve. Tangency and curvature continuity use analytic first/second derivatives of lines, circular arcs, circles, ellipses, Béziers and positive-weight clamped NURBS. Curvature contacts reject singular tangents and non-C2 interior spline knots. Point-on-curve contact adds bounded spline/ellipse membership. Solver coordinates include free contact parameters; constraints, controls and display tessellation remain separate. Explicit coincident point relations and exact endpoint contacts establish canonical endpoint identities for kernel topology; arbitrary coordinate proximity does not.

Repair Sketch stores its result as ordinary stable coincidence constraints. Its transient application-owned request/report carries an explicit millimetre gap tolerance, selected-member scope, construction inclusion, exact duplicate-relation removal and unresolved endpoint diagnostics. It joins only mutually unambiguous open endpoint pairs and preserves curve/member/point identities. Live repair uses the same validated draft and checkpoint Cancel as other sketch operations. Ambiguous pairs, driven endpoints and closure of one member onto itself require explicit user editing.

A sketch constraint has a stable `id`, `kind`, ordered `entities` and `value` expression. New member relations and dimensions use the same version-1 source record, supported by solver `tcad-native-lm/14`. Entity IDs can identify points, curve members, or the fixed plane-local references `@origin`, `@x-axis`, and `@y-axis`; these reference names are reserved and cannot be point/member IDs. Legacy relations with two or four point IDs remain supported. Dimensional kinds include `fix_x`, `fix_y`, `distance`, `distance_x`, `distance_y`, `length`, `angle`, `line_distance`, `point_line_distance`, `radius`, `diameter`, `major_radius`, `minor_radius`, and `rotation`. Length values use millimeters and angular values radians internally. Coordinate/axis offsets and line angles are signed; lengths/radii must be positive and line gaps nonnegative. Equal-radius circle/arc groups can use a driving radius/diameter dimension on a member; circles inherit an arc driver through its radius dimension or evaluated arc frame. Without a dimension, an unreferenced size source is preferred; redundant cycles use a deterministic member. Arc equality remains a numerical constraint on its point geometry. Circular tangency supports internal and external supporting-circle contact; `arc_center` relates a point to the derived center of an arc. Dimension drivers are resolved in derived sketch evaluation without rewriting the source curve expressions. Source expressions, constraints and named parameters are saved; annotation positions and visibility are saved separately in presentation state.

An extrusion references its profile, distance expression, and direction. Optional `body` and `mode` support `join`, `cut`, and `intersect`; no body and `new` create the first body. Optional `options` default to a blind extrusion, with fields `end` (`blind`, `mid_plane`, `through_all`, `through_all_both`, `up_to_face`), `start_offset`, `reverse_distance`, `target`, `target_body`, and `end_offset`. End-face references resolve against a named input body. Missing fields on older extrusion definitions retain their new-body behavior. Revolve/loft/sweep also support optional `body` and `mode`; a new-body result can retain existing bodies through its input dependency. Loft stores an ordered section list; sweep stores stations or `path_sketch`. Mirror stores its input body, plane and `keep_original`. These backward-compatible version-1 extensions use adapter 5; earlier adapters cannot evaluate the new capabilities. Older primitive definitions remain readable for existing projects; the desktop creates new bodies from sketches.

An assembly contains stable instances, numerical placements in millimeters/degrees, optional translation expressions, constraints, assembly parameters, and promoted parameter references. Instances refer to definitions independently of their placement. Nested physical assembly hierarchy and geometric dependency graphs are separate. Configurations are parameter-ID-to-expression maps; an instance can select a configuration without duplicating the definition.

Lengths are evaluated in millimeters and angles in radians internally. Serialized placement rotations are explicitly degrees. An `Expr` serializes as a string. Supported units are `mm`, `cm`, `m`, `in`, `ft`, `deg`, and `rad`. Expressions support arithmetic, integer powers, parentheses, `pi`, `sin`, `cos`, `tan`, `sqrt`, and `abs`. Local parameters use their key; cross-definition references use `@definition-uuid::parameter-key`. Division by zero, nonfinite values, dimensional mismatches, and parameter cycles produce errors. Explicit units are recommended for all source dimensions.

A typical headless command file:

```json
{
  "command": "set_parameter",
  "definition": "stable-part-uuid",
  "parameter": "thickness",
  "value": "12 mm"
}
```

The complete command enum is in `crates/cad-core/src/commands.rs`. The command line evaluates the proposed document before writing it. The desktop sends these commands into one shared draft, then requires a matching valid worker result before Apply.

Topology references contain a producer feature reference, semantic role, topology kind, and optional numerical signature. Kernel pointers, face enumeration indices, meshes, and cache handles are not native identities. Construction roles and surface/curve correspondence reconstruct references; ambiguous or missing references require an explicit replacement. Pinned imported STEP solid entity IDs refer to the immutable source file, not generated topology enumeration.

Resources contain a portable relative path, original-byte SHA-256, and kind. Imported files use `imports/<hash>.<extension>`. Saves stage changed files, durably write a journal, replace definitions, and replace the manifest last. Opening a project completes an interrupted journal. Unchanged definition files are not rewritten. Desktop recovery snapshots are separate from saved projects and can include an uncommitted draft.

Presentation belongs in `ui/layout.json`, `ui/theme.json` or `ui/theme.css`, and `ui/workspace.json`. It does not change model geometry, assembly placement, or feature dependencies. Generated tessellations and B-reps remain disposable derived data.

Sketch handle gestures do not add constraints, handle objects or cursor goals to the native document. They change source point coordinates or undriven literal curve dimensions through the existing sketch draft. Dimensional constraints, equal-radius followers and parameter/expression bindings retain their source definitions. Handle sizes below 1e-7 mm are rejected. Center rectangles use ordinary point/member IDs, horizontal/vertical relations, and a center-to-construction-diagonal midpoint relation; no new native schema is needed. Existing rectangles keep their saved constraints.

Schemas other than version 1 fail explicitly. Future schema or backend changes must introduce a documented migration and invalidate affected derived data; changing a kernel fingerprint alone must never silently rewrite a reference.

Component libraries record their source document/definition IDs, exact source revision and SHA-256, namespaced local definition IDs, definition-content hashes, and a snapshot resource. The snapshot and original resources are copied into the project; evaluation never reads a moving external source. Linked definitions are immutable until an explicit update, and registered configurations remain derived variations. Source paths are discovery hints for checking updates; missing paths do not prevent rebuilding the pinned source. Updating preserves namespaced identities; removed definitions or dependencies fail validation rather than silently replacing references.

Git component links add optional `git_source` metadata: repository, relative project folder, exact commit, update reference, and selected configuration. New links mark `definition_closure` and import only required definitions. The original source snapshot remains available for pin verification and fork ancestry. Fetch and update checks do not change the saved pin.

Default-empty `component_forks` and `feature_transfers` maps retain version-1 source ancestry. Fork records contain one original source definition and a source-to-local identity mapping. Transfer receipts retain the reviewed base for selected items and the correspondence needed to update those items again. Neither is an event log or a geometry cache; each aggregate is bounded to 32 MiB. The normative types are in `component_fork.rs` and `feature_transfer.rs`. See [Git collaboration](git-collaboration.md) for behavior and limits.

README preview metadata uses version 1 and records the exact saved source fingerprint, source revision, backend, accuracy, triangle count, units and STL hash. `previews/` and the marked README section are derived repository assets. Worker protocol 3 carries preview generation independently of the native source schema. Released `source/` folders with a release manifest reject direct saves and preview writes; use Save As to create working source.

Feature-history inspection adds no native model fields or saved suppression changes. Its transient cursor is excluded from saved presentation state. The optional `Evaluation.history` derived cache uses its own version 1 contract, source request identity and part/configuration keys; caches can be discarded and regenerated by normal evaluation. Historical display meshes are never saved as authoritative geometry or used to commit/export an earlier feature prefix.

Sketch editing intent v3 adds default-empty `splines` and `conics` maps. Interpolating splines retain source fit-point IDs, parameterization and generated control IDs; control splines retain degree, weight and knot expressions. Conic definitions retain rho-controlled quadratic, parabola, partial-ellipse or arc-slot intent, source handles and generated member/control identities. They derive through the shared modifier dependency graph rather than replacing source geometry with a renderer object. Older maps and schema version 1 remain readable.

Sketch Text contract v1 adds the omitted-empty `texts` map. Each definition saves the text, a source anchor point, em-height, X/Y offsets, rotation, tracking and line-spacing expressions, left/center/right per-line advance alignment, a pinned font resource/hash/collection face, application-owned font metrics and exact glyph line/quadratic/cubic contours, and stable glyph-slot/contour/segment member/control bindings. The local static font parser's outline callback coordinates are promoted to f64; no tessellation or renderer text is authoritative. Worker evaluation derives native closed Line/Bézier contours solely from saved intent. The original font bytes remain an immutable portable project resource for text-content updates and recovery. Compatible contour segmentation retains source identities and each member's construction flag; a deliberate Construction change applies to the whole text. Incompatible referenced retired outlines require explicit repair/detachment. Text outputs are driven; the independent anchor remains draggable and can receive ordinary sketch relations/dimensions. Detaching releases text/font intent while retaining exact current outlines. Cancel restores the operation's source and starting resource registry.

Text limits are static horizontal unshaped left-to-right glyph sequences, newlines, 1–1024 characters with nonempty outlines, 32 MiB font resources and 32768 placed segments. Missing glyphs, incomplete outlines, variable fonts, combining/format controls and contextual or bidirectional scripts fail explicitly. Kerning, ligatures, automatic fallback, text-on-path/surface and outline healing remain unsupported. Font em-height is distinct from ink/cap height. Geometry with intersecting/tangent glyph contours still requires the native profile/kernel validation; the text parser does not substitute a polygonal approximation.

Sketch Blocks contract v1 adds omitted-empty `blocks` and `block_instances` maps. A local definition owns its name, f64 insertion origin, exact native point/member intent and internal constraints; it contains no mutable model links or nested modifiers. An instance saves definition/anchor identities, translation/rotation/positive uniform scale expressions, optional literal rotation freedom, construction override, suppression and stable source-to-output point/member maps. Creating a block preserves existing output IDs. Wholly internal rigid-invariant relations move into the source; parent universe/orientation/X/Y and external relations remain on generated outputs. Explicit local-origin/axis relations can be authored within the block editor. Local definitions solve once per outer evaluation/derive pass and every equivalent instance reuses that immutable result. Generated controls add no hidden main-sketch DOFs: the independent insertion anchor supplies translation and an enabled literal angle supplies one rotation variable. Local source DOFs are reported separately. Compatible source edits preserve mappings; referenced retired outputs require repair or explicit explode. Explode retains exact current geometry and external relations, releases block binding and internal source relations, and requires an unsuppressed instance. Unused insertion anchors are removed only when unreferenced. The definition remains reusable inside the same sketch. Handle contract v2 adds projected local block controls, whose drag goals are transformed back through the exact saved placement and solved against local relations before updating all instances. Cancel restores the original source checkpoint; Accept requires the current validated shared draft.

Versioned reference geometry and surface operations are additive tagged feature definitions. Datum planes/axes/points resolve saved construction sources. Surface operations retain their profile/body dependencies and side/direction intent; separate surface outputs are valid manufactured definitions. Chamfer options default to equal distance and additionally retain two-distance or distance/angle intent and an optional first-face reference. Feature input edits reconcile consumed output branches without discarding independent bodies.

Reference geometry and assembly source contract v2 add `face_axis` (owning body and construction face reference), circular model-edge axes, and sketch-circle/arc member axes. Datum `geometry` axes preserve these source definitions. Their exact carriers are resolved at evaluation time: analytic revolution processors or proven ruled rational cylinders/conical frustums, exact circular Bernstein identities, and the solved sketch plane/member coordinates. Output ownership is independent of inherited producer/role provenance. Ambiguous topology, unsupported carriers and transformations that destroy rotational form fail rather than fitting a displayed mesh.

Surface intent v2 adds four-boundary polynomial `fill`, planar sketch `trim`, normalized U/V `trim_domain`, `untrim` and convex planar straight-edge `extend`. Parameter trim keeps the original carrier and derives new exact boundary curves by knot insertion; untrim restores its finite natural patch. Saved references and quantity expressions remain application-owned data. The adapter rejects unsupported implicit extrusion boundaries rather than substituting their guides.

Mold intent v1 adds report-only `draft_analysis`, selected-edge `parting_surface`, planar-loop `shutoff_surface`, associative positive-XYZ `shrink` and sketch-stock/parallel-plane `tooling_split`. Pull axes, parting planes, shrink centers and source body/stock references remain associative. Draft reports carry source/producer identities, exact planar angle/class records, explicitly unassessed curved faces and derived parting-edge references in disposable `Evaluation.mold_analyses` data. They are not designated outputs, meshes or manufactured bodies. Core/cavity definitions preserve their source part; only Shrink replaces its consumed body branch.

Assembly mate references retain complete nested component paths and construction sources, alignment, concentric rotation lock and captured rigid-lock placement. Numeric frames remain readable fallbacks. Drawing dimensions retain versioned type, units, precision, association and tolerance options; saved drawing annotations retain datum/GD&T/leader/center intent. Derived evaluation maps for reference geometry, solved mate frames and engineering properties are disposable application DTOs. Evaluated face records distinguish actual solid/surface body kind and output ownership from inherited topology provenance; these never replace saved definitions.


Body-editing intent v2 adds tagged `scale` definitions with positive uniform/XYZ expressions, an associative center and optional original retention. Existing `pattern` definitions have defaulted `options` for a second linear direction, skipped zero-based lattice positions, total/instance-angle spacing, rotated/fixed orientation and an associative fixed-orientation seed. Surviving copies derive construction roles from their source topology and lattice positions. These fields remain application-owned f64 intent.

Drilled-hole intent v1 adds tagged `drilled_holes` definitions. The boxed definition saves `body`, `positions` (native sketch profile), explicit stable `points`, diameter/depth/start-offset expressions, blind or through-all end, simple/counterbore/countersink head intent and reverse entry direction. Legacy `hole` definitions remain readable. Selected position points can be constrained with the ordinary sketch solver; absent point choices do not silently select profile corners. Derived hole stock and topology carriers remain inside the adapter.

Drawing intent v3 retains additive `tables` and `balloon` annotation records. Table intent v1 stores stable identity, kind, bottom-left paper position, column widths, row/text sizes and optional space reservation. BOM item-number reservations are keyed by part/configuration identity and survive hidden/suppressed rows; balloons save the selected table and the same part/configuration key. Revision rows retain their own stable IDs and explicit user-entered revision/date/approval metadata; bend rows resolve versioned evaluated sheet stock; general cells remain editable text. An invalid table, association or paper extent blocks the current evaluation.

Sheet-metal and weldment intent v1 are tagged saved operations, separate from legacy stock operations. Sheet stock retains sketch contours, thickness direction, inside radius/K expressions, complete supporting-edge references, flange length/angle and flat/form state. Weldment stock retains section/path groups, locating point/roll, corner treatment, member source IDs, trim planes/ends, end caps and sketch gussets. Evaluated sheet/weldment maps use configured definition/feature keys and exact supported manufacturing boundaries or resolved centerline/cut-plane data. These DTOs are derived; they never replace editable engineering definitions. Explicit `flat-pattern-dxf` and `cutlist` exporters read that evaluated metadata. Flat DXF selects one current blank per placed part/configuration, excluding orphan definitions, and rejects nonfinite export coordinates.

New perpendicular point-to-line dimensions save optional `distance_side: "left" | "right"` relative to the ordered line endpoints. This keeps the picked side through zero-distance edits and gives a signed solve residual; dimensions without the field retain legacy unsigned behavior. Mirror operations that reflect both targets reverse the side. Smart Dimension can save an associative construction conversion of an exact straight model edge; selection alone does not create that geometry, and canceling the dimension restores its starting source and any parameter promotion.

New bound conversions save `construction_orientation: true`: the native construction curve parameter direction assigns stable output controls, independently of incident-face traversal. Omitted/false retains the older incident-face ordering. Native edge descriptors expose the construction carrier in the current adapter. New dimensions reuse only construction-oriented conversions; an older conversion keeps its authored controls and can coexist with a new independent construction reference.

Workspace presentation saves navigation preference contract version 1 in `navigation`, and camera roll in `roll`. Omitted fields retain defaults. Direction switches, sensitivity, precision modifier, native rotation and smart zoom are view intent, independent of geometric source, renderer objects and application undo. The native platform adapter translates gestures into application-owned motions; unsupported or unavailable platform events do not create synthetic hardware gestures.

Rib intent v1 stores a source sketch, open-contour member anchors, supporting body/face, scoped joins, fill direction, unit-aware thickness, thickness side and explicit attachment overlap. Direct-edit intent v1 stores a body and construction face references with a tagged signed offset, rigid movement, delete/heal or replacement-plane method. Body-filter intent v1 stores explicit solid-output scopes and owning-output/construction-face anchors with Keep/Delete modes. Surviving whole solids retain source topology; an empty body set has finite disposable display bounds. Overlapping scopes that alias the same exact native solid are rejected using transient complete topology correspondence; no native IDs become saved authority. Suppression aliases every compatible consumed solid/surface source branch and preserves merged ancestry, rejecting conflicts or mixed kinds. Sketch source admission excludes suppressed generated geometry from active modifiers and native datum/mate consumers, while independent controls shared with active operations remain usable; the solver/cache fingerprint reflects this behavior.

Reference-curve intent v1 stores ordered stable composite source records, associative spatial point records/interpolation, or helix/spiral axis/radial/radius/pitch/turn/phase intent. Evaluated native-piece ancestry, analytic descriptors and proven analytic display bounds remain derived DTOs; `Evaluation.reference_curve_meshes` contains separate edge-only caches excluded from body properties. Sketch dimension-group intent v1 adds omitted-empty `Sketch.dimension_groups`. Existing native constraint records remain the only dimensional expression/driving-mode authority. See [grouped dimensions](sketch-dimensions.md).

Curve-pattern intent v1 stores a source body, native sketch/reference path, count/range expressions, parameter or supported exact-distance spacing, direction, fixed/tangent orientation, authored frame-up, associative seed alignment, source retention and stable skipped station slots. Surviving copy roles derive from owner, zero-based slot, exact source topology and path construction intent; native indices or coordinate buckets do not identify copies.

Placement-pattern intent v1 stores whole-body input, a Sketch Driven/Table Driven kind, associative seed/axis and authored placement records with point source, rotation and skip state. Sketch equation-curve intent v1 adds omitted-empty `Sketch.equations`, keyed by generated member ID. Each definition retains ascending polynomial X/Y expression coefficients, range, angle, independent anchor and reserved Bezier control IDs. Materialization is algebraic rather than sampled fitting. Generated controls are excluded from independent solve variables; constraints/dragging resolve the independent anchor. Compatible IDs survive edits and retiring referenced controls fails. Reference-geometry intent v5 adds signed angular bisectors and tangent planes with native owning-body/face references plus normalized parameter or associative point anchors. Kernel objects and derived plane frames are not saved. Proven bounded carrier domains, regular derivatives and exact provenance gate evaluation; unsupported trims and ambiguous inverses fail. Coordinate-system intent remains v1.

The additive `import_surfaces` operation stores a pinned resource ID and 1–4096 distinct STEP shell-based surface-model entity IDs. Native ancestry retains resource SHA-256 plus model/shell/face/edge entity identities; imported definitions remain independent of disposable native indices. Supported mixed solid/surface imports retain separate feature outputs in their owning part. The parsed-cache adapter recognizes the exact inherited fields of manifold-surface and geometrically-bounded-surface representation subtypes without changing pinned bytes, entity IDs or links; unsupported geometric sets/mapped items still fail. All DATA sections are retained and duplicate entity IDs reject. Conversion-record completeness is required but does not certify arbitrary UV trim semantics: strict carrier/domain guards reject discarded or ambiguous trim intent. Finite affine rigid placements and homogeneous positive length-unit contexts are required. Broader periodic/swept/trimmed surface imports remain engineering work.

Shell wall intent v1 adds omitted-at-default boxed `options` to the existing `shell` operation. `outward` chooses which material boundary is offset; `face_thicknesses` stores stable face references with unit-aware expressions, independent of renderer/kernel faces. Removed faces cannot also receive a retained-wall override. Supported offsets preserve exact planar/circular boundary geometry and publish explicit engineering errors for collapsed cavities, intersecting pocket envelopes and unsupported carriers. The same draft, current-result validation, Apply and checkpoint Cancel govern all thickness controls.


Configuration intent v1 extends the legacy part parameter-override map with `Part.configuration_details`, `Assembly.configurations`, and `Document.active_configurations`. Component-pattern intent v1 adds `Assembly.component_patterns` with saved seed IDs, count/spacing/axis expressions, reserved occurrence and copied-mate identities. Pattern, drilled-hole, cut and Shell construction roles use compact structured payloads behind their semantic role strings. Generic `construction:` roles retain canonical source-reference closures plus ordered constructor intent for walls, openings and partitions; library copies remap that source closure and preserve operation intent.
