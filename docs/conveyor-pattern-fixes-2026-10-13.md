# Referenced linear patterns — October 13, 2026

This implements P1-08 from the [conveyor usability review](conveyor-project-usability-review-2026-10-13.md) in part and assembly patterns. Compilation and linting are evidence of source integration; interactive acceptance remains with the user. No tests, assertion probes, UI driving, or smoke checks were run.

## Modeling intent and evaluation

Body patterns have an optional application-owned direction source containing a straight `AxisSource`, positive length spacing, reversal, and complete source/owner occurrence paths when the reference is in another component. Directions can use named origin/reference axes, coordinate-system axes, straight planar or spatial sketch members, and straight model edges. Native provenance resolves model edges; a missing, ambiguous, curved, or collapsed source fails instead of supplying a display-polyline tangent. Direction dependencies participate in the feature graph.

In-context directions wait for the assembly solve. An optional f64 occurrence-transform resolver uses current solved placements at every level of the complete path and transforms the direction into the pattern owner's coordinates. This does not use the provisional source traversal's pattern placements. Assembly placement feedback into its own mate/pattern geometry is rejected through the existing dependency-closure guard. References to a different explicitly configured part carrier are rejected when that carrier is not the currently active geometry context; activating the matching part configuration or choosing an independent local axis is required. This protects source meaning rather than silently reusing another configuration's geometry.

Assembly component patterns now use a positive spacing and reversible axis source, with a numeric direction-vector fallback. The existing direct-participant plus nested reference path represents the full occurrence relative to the pattern owner. Reference frames are evaluated in their configured leaf, composed through the nested placements, and transformed into the owning assembly. Changes to referenced geometry and solved placement therefore change the pattern's evaluated directions. Both first and second directions support these references. Each direction count includes the seed; count expressions accept 1–256, and active output remains limited to 4096 generated component occurrences.

Two direction counts produce a grid of translated seed groups. Native occurrence reservations use persistent `[column,row]` coordinates rather than flattening coordinates through the current first count. Count shrink/growth, second-direction changes and configuration changes retain the existing coordinate/seed identity and internal copied-mate reservation. Reservations cover the union of configured grids, avoiding an artificial Cartesian product of unrelated configuration maxima. Existing version-1 component patterns remain readable and retain their IDs; document commands upgrade their source to version 2. Removing a seed clears its deleted copies' component-placement/configuration overrides. Make Unique retargets direction geometry only for complete reference paths entering the changed instance (including seed-generated copies); sibling paths keep their original shared sources. Making an occurrence-bound pattern owner itself unique is explicitly rejected before mutation, because safely reanchoring the original/shared owner definition requires a separate source migration. Ordinary local-axis/sketch-pattern owners can still be made unique. New optional body-direction fields preserve legacy vector-source decoding.

## Presentation and interaction

The docked body-pattern controls expose reference choice, spacing and reversal for both directions, with explicit XYZ vector entry available as a fallback. Component patterns default to direction/spacing controls; an optional second direction exposes its own count and source. The component editor shows the owning assembly and selected seeds before the fields, explicitly identifying a complete subassembly seed. Candidate seed selection is collapsed, searchable and virtualized, and its height is styleable. Shared confirmation owns Apply and Cancel.

`Pick direction on model` explicitly arms a reference pick. It accepts current native straight edges or datum axes without changing the editing owner, and stores the complete occurrence paths. Native sketch-member choices list straight 2D and 3D members, including construction centerlines. An armed picker also shows source-bound line candidates in the model viewport and captures their stable member IDs before ordinary sketch opening or body selection. The current editing occurrence is prioritized; the visible candidate set is bounded, while the named reference chooser remains available. Ambiguous projected overlaps are rejected with a named-selection/rotate/isolate instruction. Hidden, transparent, or zero-width candidates cannot capture a pick, and `renderer-pick-radius` can style their screen-space hit radius. Cancel or tool completion removes the temporary pick state and restores the prior context-picking choice. Curved edges and planar/rotational face normals are not silently converted into a linear direction.

Workers publish disposable f64 pattern-guide data independently of rendering. The semantic presentation includes owner-local source fields, direction-pick/reverse actions, source-bound seed controls and search/expansion, plus root-space arrow descriptors. Viewport arrows require matching document, backend, generation, revision and draft/edit identity and inherit role/identity/class styling. A differently configured or suppressed occurrence never borrows its base definition's guide. They show the spacing direction and reverse with the same source operation. Neither arrows nor their rendered geometry are authoritative model inputs.

The shared draft, validated-current Apply guard, checkpoint Cancel, and single undo transaction continue to own all edits. The new directions do not change the existing whole-body pattern scope: feature replay and face-pattern modes remain separate gaps. Component mirror, skipped component grid positions, external mates on driven copies and non-linear component-pattern families also remain gaps.

Part-pattern edge picking uses the original native input body from the checkpoint history, including when editing an existing pattern. A picked edge highlights without changing the owner or seed selection. The direction cannot reference the current pattern or a feature that depends on it; downstream sketch candidates are also excluded. Independent external directions retain their occurrence paths instead of borrowing the pattern output's topology.
