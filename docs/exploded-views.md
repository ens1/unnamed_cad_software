# Exploded assembly views

`Assembly.exploded_views` saves version 1 application-owned presentation intent. Each named view has a stable identity, optional owning-assembly configuration, and ordered stable steps. Targets retain complete occurrence paths, including nested subassemblies and reserved component-pattern copies. Selecting a subassembly moves every active descendant once. Overlapping ancestor/descendant targets in one step fail rather than double-transforming components.

Each step retains scalar XYZ direction expressions, signed length distance, angular rotation, a length-valued rotation pivot, suppression, and optional local leaf anchor expressions for displacement connectors. The normalized direction and pivot use the owning assembly's assembled frame. Rotation about that direction happens first; translation follows. Steps compose in saved order over the current configured mate-solved placements. Fixed components may participate because these are presentation transforms. Connector segments record each step's displacement between the before/after positions of each local anchor; they describe the saved presentation route, not a swept motion or collision certificate.

The docked Assembly manager creates and edits views, selects components/subassemblies through saved full-path breadcrumbs (up to 4096 listed choices, with model occurrence selection and saved source available for broader sets), edits quantities and connector anchors, adds/deletes/reorders/suppresses steps, and shows assembled, intermediate or fully exploded stages. View controls select saved views and hide/show connectors. The same geometry, native topology references and complete occurrence paths drive exploded rendering, picking, highlighting, datum/sketch overlays and fit. Starting a modeling operation restores the assembled display and rebases a picked point into mechanical coordinates. Mate placements, mass properties, STEP and STL exports retain assembled coordinates.

Persistent worker evaluation validates the current expressions and produces disposable f64 stages and connectors. The shared draft rejects stale worker results; invalid source cannot Apply. Cancel restores the starting document checkpoint and prior display selection; Apply uses one document undo. Semantic view/step data and actions remain separate from layout and styling. Pinned component imports namespace view, step and occurrence identities alongside assembly definitions.

Current scope is the document's root assembly and its selected configuration. A configuration-bound view is available when that configuration is active. A nested assembly can retain its own views, but those become displayable when it is opened as the root; they do not silently alter a parent's scope. Suppressed targets remain saved and produce an inactive-target report when they have no active leaves. Deleting or replacing referenced components requires explicit target repair. A drawing that uses a view prevents deleting that view until its source is changed.

The source is bounded to 128 views per assembly, 128 steps per view, 1024 targets per step and 64 IDs per occurrence path. Root display caches allow one million placement records and one million cumulative connector records, with a combined 64 MiB conservative byte budget. The source permits 16384 target references per document; root evaluation permits eight million target path comparison units and exploded display coordinates within ±1e12 mm. Exceeding finite/resource bounds fails explicitly and leaves committed source intact. Automatic spacing, draggable explode handles, animation, nested inherited explode states, automatic route lines, rotation arcs, collision checks and alternate mechanical positions remain work. Compilation/lint evidence does not establish interactive acceptance; no code tests or manual UI exercises were performed.
