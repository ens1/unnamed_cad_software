# Bounded topology source closures

Topology provenance uses the application-owned `tcad.topology-closure` contract, version 1. It stores complete source descriptors in a canonical dependency table rather than recursively copying and escaping their complete ancestry into every incidence tuple. The outer `construction:`, `pattern:`, `hole-position:`, and `hole-intersection:` role prefixes retain their meaning.

A closure contains `contract`, `version`, `root`, and `references`. The root is the constructor intent. Each table entry retains its source producer, topology kind, structured role, and complete constructor intent; `{"$tcad.source": n}` refers to an earlier descriptor in this table. Nested closures are imported and deduplicated without expanding a source tree. Dependencies precede users, and descriptors at the same dependency depth are sorted by their full canonical content. Native IDs, geometric coordinates, traversal order, and hash digests do not name descriptors.

Boolean split-face boundary and split-edge endpoint signatures use a separate local descriptor table during construction. Boundary and endpoint tuples refer to its indices. The closure encoder merges these sources with the constructor's explicit sources. This prevents both repeated ancestry copies at each incidence and the repeated JSON-string escaping that previously exhausted the sheet Normal Cut / Relief provenance budget on a short formed history. Boundary/endpoint multiplicity and tuple meaning are preserved; only unordered incidence sets are canonically sorted.

Normalization is memoized within each topology-history step. Serialization is charged for distinct source descriptors, actual new signature output, and constructor output, rather than repeatedly normalizing the same input face/edge for every lookup and uniqueness check. Bounds remain enforced: 16 MiB per history step/closure, 64 MiB published history, 1,048,576 traversal work units, 65,536 distinct source descriptors, and 256 source-dependency levels. Cyclic, forward, missing, malformed, or unsupported-version source links fail explicitly. Diagnostics identify traversal, serialization, descriptor storage, ancestry depth, or published-history limits when applicable.

Legacy structured tree roles normalize through the same canonical identity. The historical topology-component signature format embedded JSON descriptors as strings; normalization recognizes that constructor grammar and converts those strings into real source descriptors. Face/edge, face-attached sketch-plane, tangent-plane, reference-point, native-reference-curve, and weld-seam resolution compare canonical source identities. A malformed or excessive legacy role reports a failure; numerical signatures do not silently replace established source identities.

Drawing dimensions and face-origin anchors, Keep/Delete Bodies anchors, model-edge reference curves, surface-construction face sources, curve-pattern paths, and sweep reference paths use that same bounded identity comparison. Drawing source candidate lookup has an explicit admission bound, and reference normalization errors propagate to the user. Native constructor collision checks within one fresh evaluation may retain exact role comparison because they compare uniformly constructed current descriptors. Explicit reference-repair transaction freshness still compares the complete authored source, rather than ignoring concurrent definition changes.

Native library import and Make Unique traverse all readable table descriptors during identity remapping and then recanonicalize the closure. Reordering a constructor source table also rewrites the explicit prismatic Boolean interval/plane indices; literal paths/text remain subject to the library's existing literal-field policy. Saved feature definitions do not require a document-schema migration. The adapter fingerprint changes so old evaluation caches rebuild and publish compact histories. Unsupported split components with indistinguishable exact ancestry remain unsupported.

This changes representation and reference resolution, not the native geometry algorithm. It does not raise the geometry/provenance bounds, substitute mesh geometry, or establish support for unrelated curved Boolean cases. Compilation, formatting, and linting are the available implementation checks; no code tests, probes, or interactive acceptance exercises were performed for this change.
