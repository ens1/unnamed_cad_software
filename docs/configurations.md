# Configurations, design tables, and component reuse

Configuration contract version 8 stores named definitions, inheritance, source overrides, feature and sketch dimension expressions, scalar configured repetition equations, component placement and free curve mate seeds, and selected configuration IDs in native documents. Versions 1–7 definitions and tables remain readable. It contains application-owned IDs, expression text, and data; no renderer or kernel objects are authoritative. The existing part `configurations` parameter-override maps remain readable. Editing one migrates that row into the richer `configuration_details` form. Assembly configurations use their own definition map. Empty additive fields are omitted so older pinned library source hashes remain stable.

## Supported configuration behavior

The docked Configurations editor selects a part or assembly, creates named or derived configurations, duplicates a resolved configuration, and edits its name, description, parent, and overrides. Parent chains resolve from oldest ancestor to child; explicit child values win and omitted values inherit. Missing parents, inheritance cycles, ambiguous names, broken source references, and incorrect owner scopes are reported. Deleting a selected configuration or a parent with derived children is rejected.

| Part choices | Assembly choices |
| --- | --- |
| Unit-aware parameter and feature dimension expressions; feature and sketch suppression; material; custom properties; BOM naming, part number, description, and exclusion | Unit-aware parameter expressions; component, component-pattern, and mate suppression; child part/subassembly configuration selection; per-coordinate component placement and free Path/Slot/Cam parameter seeds; custom properties and BOM exclusion |

Suppression controls distinguish inherited, resolved, and suppressed state. A sketch suppression override controls its Profile feature. Configured feature suppression from the tree or on-click action edits the selected configuration. Suppressing a terminal body modifier restores its consumed predecessor outputs; a suppressed terminal Boolean restores both branches. Suppression of an initial sketch, datum, first body, or multi-input operation that still has an unsuppressed dependent reports the actual source/dependent relationship rather than fabricating a result or silently suppressing the dependent. Suppressing an assembly component omits its placements and its involving mates. BOM exclusion preserves viewport geometry and propagates through excluded ancestor assemblies.

The Equations tab edits existing parameter expression text and unit dimensions and adds parameters. Values and errors come from the current worker evaluation. Expressions may reference other named parameters; dimensions are checked by the shared expression engine. Equation edits affect the base parameter definition; named configuration parameter overrides appear in the configuration and table tabs.

The Table tab edits per-configuration parameter and typed feature dimension cells and selects the row for live evaluation. Feature dimensions can be filtered by feature or field and edited in grouped detail controls. See [configured feature dimensions](configuration-dimensions.md) for supported source fields and the semantic value adapter. Its suppression summary links to the detailed configuration controls. Local JSON and CSV import/export preserve source intent and stable native IDs; import can merge or replace the configuration table. JSON includes the native table version and owning definition. CSV accepts quoted commas/newlines and rejects malformed quoting, duplicate columns, ragged rows, and missing names. Imports resolve unique parameter, feature, sketch, component, pattern, material, parent, and child-configuration names to native IDs. Mate columns use native mate IDs. A matching existing configuration name updates that configuration's ID. Table replacement cannot silently remove a referenced selection, and failed import validation leaves definitions unchanged.

CSV fixed columns are `id`, `name`, `parent`, `description`, `material`, `finish`, `bom.exclude`, `bom.name`, `bom.part_number`, and `bom.description`. Additional columns use `parameter:ID`, `dimension:FEATURE_ID:/operation/field`, `feature:ID`, `sketch:ID`, `component:ID`, `pattern:ID`, `mate:ID`, `configuration:INSTANCE_ID`, `placement:INSTANCE_ID:x`, `placement:INSTANCE_ID:y`, `placement:INSTANCE_ID:z`, `placement:INSTANCE_ID:rx`, `placement:INSTANCE_ID:ry`, `placement:INSTANCE_ID:rz`, `curve-seed:MATE_ID`, or `property:NAME`. Dimension paths are relative to the operation, such as `/distance` or `/options/start_offset`; the operation prefix is not part of the path. Arrays with authored record IDs use `@id=RECORD_ID` segments and resolve against current record order. Anonymous arrays remain positional; semantic fields disclose that limit. Empty cells inherit. Suppression accepts true/false or suppressed/resolved. A child-configuration cell containing `default` clears the explicit occurrence choice and follows the selected configuration of its definition. BOM names accept document, configuration, or custom.

Every accepted edit enters the common document draft and the persistent worker updates the preview. Invalid source text stays editable and blocks OK. OK requires the evaluation for the current draft identity and commits one undoable operation; Cancel restores the starting session checkpoint. Opening and closing an unchanged editor adds no undo entry. Table files use atomic local writes. The native definitions and selections participate in ordinary save, recovery, and local Git workflows.

## Configuration-specific assembly placements

Assembly overrides contain omitted-empty `component_placements` and `mate_curve_seeds` maps. The owning assembly's stable instance ID identifies a pose; its `translation` and `rotation_deg` arrays contain three optional f64 coordinates each. Translation uses millimetres; rotation uses the same Euler XYZ degrees as ordinary native `Placement`. Omitted coordinates inherit independently through the parent chain and ultimately from base placement. This stores rigid source seeds, not a second authority beside the mate solver. Pose construction requires finite coordinates and a finite rigid frame. Assembly configuration state never changes a part's local shape.

The Configurations detail editor groups each component's six coordinates compactly, with an independent override checkbox for each coordinate. Clearing a checkbox resets that coordinate to inheritance. The base scope edits base source coordinates directly; named scopes leave the base and sibling configuration sources intact; derived children continue to inherit any coordinates they have not overridden. The design-table tab also exposes pose fields for named rows. Fixed values accept exact unit constants such as `2 in` and `pi rad`, with unitless values interpreted as millimetres/degrees. CSV exports canonical units. Named component references import through unique names or stable instance IDs. Numeric placement cells cannot contain parameter references: configure the driving assembly parameters for expression-based translation instead.

Accepted assembly Move/Rotate writes its solved component seeds to the explicitly selected Base or active named source scope. Free Path, Slot, and Cam parameters follow that pose in the same scope, using finite canonical fractions in 0..1. They are inherited source hints; a hard mate Fraction expression is never replaced. Fixed components are not modified by Move/Rotate. Numeric translation overrides for components with translation expressions are rejected, and expression-driven translations remain authoritative. Patterned copies cannot receive independent placement overrides; configure their seeds or driving pattern. Seed poses are applied before pattern placement and mate solving. Suppression is applied after pose materialization, so suppressing/restoring a component retains its saved configuration pose without leaving involving mates active.

All pose controls publish stable `configuration-placement-field` and `configuration-placement-group` identities over the existing typed configuration value adapter. Units, inherited/overridden/expression-driven states, control availability, parent grouping, diagnostics, and editable values remain independent of native layout. Stale editor generations and source revisions reject writes. Invalid field text remains editable and blocks confirmation; cancelling discards the shared draft. Library insertion namespaces placement and curve-mate keys; instance/mate deletion cleans their overrides. Changing a mate from free curve motion to a hard fraction requires resetting any corresponding configuration seed overrides first.

## Configured evaluation and reuse

Definitions may have a globally selected named configuration. Each component occurrence may select another named part or subassembly configuration; clearing its explicit choice follows its definition's active selection. Simultaneous configured part meshes, reference geometry, sketches, history, fabrication metadata, and properties have distinct `definition@configuration` identities. Configured subassemblies also have distinct evaluated placements and exact mate frames. Full nested instance paths identify repeated components independently of the definition they share.

The worker materializes each scope from authoritative base definitions, applies inherited parameters and suppression before evaluating geometry, resolves exact configured mate references, and solves children before their parents. Configured material is used by rendering, inspection, flattened BOMs, and cut lists. Drawing source placement and tables use the same evaluated occurrence configurations. STEP export retains assembly hierarchy and configured definition identity instead of flattening different variants into one model.

Making a seed component unique remaps feature ownership, configuration feature-override keys, and mate, circular-pattern, or drawing geometry endpoints only on occurrence paths entering that component. Its sketch/member/configuration/material identities remain locally scoped. Drawing balloons attached to that occurrence follow its new BOM definition; direct definition sheets and shared siblings keep their sources. Shared siblings retain their original references. Linked native libraries namespace configuration, pattern, occurrence, and copied-mate IDs with the other application source identities. Explicit library updates preserve the host's selected configurations and reject updates that remove one of those selections. Source remapping preserves names, notes, properties, and literal file paths. Construction provenance uses structured role payloads whose nested definition/feature/point sources are remapped; ambiguous legacy intersection roles require a replacement pick.

A part/configuration owns its geometry. An occurrence-selected ancestor configuration that changes external parameter equations used by that geometry is rejected, because the existing identity cannot represent two different results for the same part/configuration. Use an explicit child configuration or a unique definition for that case. There is no occurrence-forced base mode when its definition has an active named configuration. Excel-linked workbooks, configuration-specific display states, sketch solver dimension columns, non-expression numeric/integer fields, and flexible subassembly configurations remain work in scope. Interactive acceptance belongs to the user; no code tests or manual smoke tests were added or run.

## Associative component patterns

Component-pattern contract version 1 stores the seed component IDs, count expression, placement mode, stable occurrence reservations, and copied internal mate reservations. Linear patterns use three unit-aware step expressions. Circular patterns use a center and direction or an associative component axis/plane-normal source, an angle expression per increment, and an option to preserve the seed orientation. Exact axis sources retain the full nested component reference path and resolve in f64 during worker evaluation after seed mates solve. The source numeric fields remain explicit legacy/default values; an associative source must resolve successfully.

Count includes the seed and is an integer from 1 to 256. A pattern allows at most 4096 generated occurrences. Native reservations are allocated for the maximum driven count across the owning assembly's configurations and survive count reduction, suppression, and restoration. Pattern dependencies from generated seeds or axis components are ordered and cycles are rejected. Copies retain their shared source definition/configuration, while configuration overrides can suppress individual copies or select a different child configuration. Generated occurrence placement edits, direct deletion, and Make Unique are rejected with the appropriate pattern/configuration edit action.

Internal mate copying remaps both seed participants to their reserved copy IDs while retaining nested geometry endpoints. Each copy resolves its current configured source frames. The copied relations are validated at the pattern-driven placements; the mate solver does not move the copies away from their driving pattern. Changing copy configurations or preserving orientation in a circular pattern can make those relations incompatible and produces an explicit error. Deleting a pattern or removing a seed cleans its configuration override keys and rejects dependent patterns that still use the removed occurrence or axis.

External mates on generated copies need coupled pattern constraints and are currently unsupported. Mirrored components need handed geometry rather than a rigid placement and are not implemented. Additional equal-spacing, second-direction, skipped-position pattern modes, standalone copy-with-mates placement solving, exploded views, flexible subassemblies, and virtual-part workflows remain separate engineering work. The docked pattern editor uses the same current-validation, checkpoint Cancel, and one-undo commit rules as the rest of the application.

The current pose inspector reports an ambiguous saved configuration ID literally
named `base` and declines controls for the Base / matching named scope, preventing
silent misrouting. Core source IDs and geometry evaluation remain unchanged;
other named scopes remain editable. This is a renderer limitation to replace
with fully typed scope selection, not a saved-source identity restriction.
