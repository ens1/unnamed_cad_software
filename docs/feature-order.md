# Authored feature order

Feature-order contract 2 preserves the ordered part feature definitions and all feature, sketch, body and topology identities. The `reorder_feature` domain command accepts a part, feature identity and destination index. The `reorder_feature_relative` command accepts stable moving/anchor feature identities and a before/after intent; it resolves the final index against the current source. Both validate the complete proposed local order against explicit dependencies, including converted model-edge dependencies of sketch profiles. A consumer cannot move before its construction source. Suppressed definitions retain their relationships; reordering does not detach or retarget them.

Drag a feature-tree row before or after another row in the same part. The insertion marker uses the actual styled row bounds and has a disabled state for dependency conflicts. Dragging near the tree's scroll boundaries scrolls the list. A document change during the gesture rejects its stale payload. Feature-tree context actions and theme-independent feature/selection actions also expose Move Up and Move Down. The docked Feature Order manager exposes stable before/after destination actions for custom layouts and keyboard-accessible controls.

The desktop starts one tool checkpoint, submits the source edit to the persistent worker draft, and requires its current valid result for Apply. Cancel restores the starting checkpoint; Apply is one undoable source operation. Further changes within the manager use that same checkpoint. Source order is shared across configurations. A reorder is a source edit; cached History inspection remains a separate display operation without a rebuild. Reordering is unavailable during another modeling operation, Settings, recovery, or cached History inspection.

Presentation roles include `feature-drop-marker` (`ready`/`disabled`, color and stroke width), `feature-drop-hint`, and `feature-reorder-target`. The `feature.reorder-relative` semantic action carries document/source, owner, moving-feature and anchor identities; an outdated source or destination is rejected. The catalog computes legal bounds once before publishing its destination choices.

Editable rollback/freeze and automatic dependency retargeting remain gaps. The command rejects an invalid requested order rather than manufacturing a different dependency graph. Compilation, formatting, linting and source review are engineering verification; interactive acceptance belongs to the user.
