# Replaceable contracts

TCAD's document and command schemas are the product boundary. No Bevy, egui, cgmath, or Monstertruck object appears in the native document, semantic presentation descriptors, or process protocol. Authoritative coordinates are f64; only the viewport adapter converts to f32.

| Contract | Current implementation | Replacement responsibility |
|---|---|---|
| Document + commands | `cad-core` JSON DTOs | Preserve stable IDs, units, graph semantics, explicit schema migrations |
| Geometry service | Framed protocol v1 | Preserve request identity, cancellation, diagnostics, backend identity, derived mesh contracts |
| Operation/mesh adapter | Monstertruck 0.4.1, adapter 21 | Implement operations, exact B-rep validation, reference reconstruction, tessellation; report unsupported cases |
| Constraint solver | Native scaled damped SVD solver v12 | Record solver identity, report convergence, residual and degrees of freedom |
| Sketch handles | Application-owned handle and drag-target contracts v2 | Preserve stable targets, f64 plane coordinates, engineering constraints and explicit unsupported capability errors |
| Project store | Recoverable multi-file JSON store v1 | Preserve deterministic definitions, relative resources and crash recovery |
| Feature-history display | Application-owned stage/cache contract v1 | Preserve source identity, body branches, sketch visibility, configuration geometry and view-only inspection commands |
| Semantic presentation | `presentation::project` | Expose IDs, typed data, expressions, prior values, relationships, states and commands |
| Layout/style | Versioned core contracts; hierarchical native composition, typed bindings, validated CSS cascade and local resource packages | Keep data/action identities and editing transactions independent of renderer registration, collection templates and visual organization |
| Visual finishes and lighting | `cad-core::appearance` contract v1 | Preserve f64 finish/mapping/lighting values, pinned texture resources and independent engineering materials |
| Desktop renderer | Bevy 0.20.0 + egui 0.43.1 | Render derived artifacts and adapt gestures; keep application state outside renderer objects |
| Version control | Git process adapter | Preserve ordinary repositories and explicit semantic conflicts |
| Manufacturing/export | Application DTOs + exchange adapters | Preserve source identity, units, tolerances and artifact meaning |

`cad-core` owns definitions, expressions, solvers, persistence, transactions, semantic presentation, manufacturing metadata/exports, release manifests, and semantic diffs/merges. `cad-kernel` contains all vendor geometry. `cad-worker` is a persistent native geometry process. `cad-desktop` adapts domain commands and derived geometry to windows, gestures and widgets. `cad-cli` uses the same core and geometry evaluator without the renderer.

Evaluation identity includes protocol version, worker generation, committed base revision, draft ID, draft edit number, source SHA-256, and backend fingerprint. A result must match all fields. Suppressed operations alias input provenance explicitly. Failed rebuilds invalidate the prior cache key before adapter histories change.

Superseded active evaluations terminate their worker; subsequent requests create a fresh process. Idle workers are reused. Deadlines isolate runaway work. A distinct export worker prevents an export from replacing a preview. Geometry panics are caught in the worker and invalidate the evaluator.

The committed document remains independent of the draft. A failed preview preserves committed geometry. Apply accepts only the current validated evaluation and produces one undo record. Cancel discards the draft. Undo/redo increment revision identity and reevaluate. Navigation and graph positions are presentation state.

The desktop's modeling property managers take a session checkpoint before starting a tool. Operation cancellation restores that checkpoint; confirmation waits for a matching valid evaluation and uses the same Apply path. `cad_ui` supplies the familiar CAD command bar, feature tree, property controls, and status widgets. Their roles remain separate from the declarative layout resources and from authoritative definitions. Startup creates an empty part document; loading an example is an explicit command.

The current adapter verifies B-rep closure and geometric consistency, checks resource hashes, solves constraints, and tessellates for display. Meshes are not used to reconstruct STEP solids. STL and tessellated drawing sections intentionally use meshes; STEP uses evaluated analytic/NURBS B-reps and an assembly product graph.

Adapter 5 includes exact B-rep construction for contained blind pockets in cuboids, equal-distance chamfers on convex planar edges, and single-plane corner removal from convex polygonal through-cuts. Shared edge and vertex identities are retained when clipping adjoining planar faces. Curved faces and pocket boundaries are retained only when wholly on the kept side; intersecting unsupported curved boundaries fail explicitly. These implementations remain inside `cad-kernel`; documents retain ordinary sketch, extrusion, and chamfer operations.

Adapter 5 adds application-owned mixed sketch members with exact lines, circular arcs, ellipses, circles and polynomial Bézier B-reps. Sketches evaluate into closed material faces and open wires; nested contours form holes and construction members do not make solids. Display polylines are a separate protocol DTO. Extrusion end conditions, starts and second-direction depth remain source intent, independent of the kernel. Through All obtains conservative exact control-hull bounds and refuses unsupported conversions. Revolve, loft and sweep result modes use the same input-body contract, and mirror preserves reflected shell orientation. The adapter fingerprint invalidates prior derived caches without rewriting document references.

Adapter 6 corrects validation of implicit Boolean intersection curves. Monstertruck 0.4.1's surface inclusion check tests their guide B-spline, whose chords leave curved carrier surfaces even when the actual projected intersection curve is valid. The adapter instead checks exact carrier identity against the owning face and projection convergence/residuals at the ends and four subdivisions of each guide knot span, using the kernel's existing geometric precision. Shared edges are checked once; finite coordinates, curve/vertex endpoint correspondence and closed oriented shells remain required. Ordinary curve inclusion checks are unchanged. Unresolved projections, unmatched carriers and unsupported guide types fail explicitly. No geometry is replaced with the guide polyline and no tolerance is enlarged. The adapter fingerprint changes to 6, invalidating derived evaluations; definitions and topology reference schemas need no migration. Compilation/lint establish code consistency; interactive geometric acceptance is left to the user.

Adapter 7 replaces cuboid Shell/Draft with exact supporting-plane operations on convex polyhedra. Retained shell planes move inward by the requested perpendicular thickness; removed planes stay at the original boundary. The inner hull is formed by triple-plane intersections in local coordinates. Opening rims are planar polygon differences, including adjacent openings; shared vertices/edges and collinear boundary subdivisions avoid T-junctions. Closed cavities use an inverted inner boundary. Draft rotates selected supporting planes around their intersection with an arbitrary perpendicular neutral plane. Collapse, unbounded half-spaces, closed openings, concave/curved bodies, existing cavities and coplanar subdivisions fail explicitly. Retained carrier surfaces preserve provenance; opening rims have new feature roles. Contained pockets use proven control-hull containment in convex planar supporting half-spaces, rather than axis-aligned box bounds, and keep analytic curves. Other cuts retain the general Boolean path. Validation precedes topology-history publication. These changes remain inside the replaceable kernel adapter, and definitions need no migration.

The semantic tool catalog carries stable command IDs, labels, grouping, and prerequisites separately from native menu appearance. Projection also exposes sketch members and assembly mates. Native history/graph cards and view-cube/callout overlays consume document/semantic data; graph positions, UI density, layout and themes are presentation state. Geometry still runs in persistent worker processes.

`cad-core::selection_actions` owns version 2 of the selection action contract: geometry, feature, sketch entity, reference and application-object targets, relevant command identities, groups, availability and disabled reasons. It carries stable feature IDs and topology provenance without widget objects or popup coordinates. The desktop adapter presents those descriptors beside the clicked geometry or feature, or in a user-defined `selection-actions` dock, and routes modeling through the existing draft and validation path. Popup anchors, dismissal, dimensions and colors belong to the desktop presentation adapter.

`cad-core::sketch_actions` owns sketch relation/dimension intent v1. Entities reference stable point/member/constraint IDs or reserved plane-local `@origin`, `@x-axis`, and `@y-axis` identities. These are fixed references, independent of a renderer and of tessellation. Relation applicability and Smart Dimension choices are projected through the same selection capabilities. The native adapter adds Shift selection, dimension editing, parameter promotion and movable annotations; those positions/visibility/style remain presentation data. `presentation::sketch_elements` publishes pending members, points, constraints and references, including invalid draft values, for custom bindings.

Solver fingerprint `tcad-native-lm/2` adds member/reference constraints and uses a signed, wrapped line angle residual to make zero-angle relationships solvable. Prior derived caches are invalidated by the fingerprint; old point-ID constraints remain readable. Circle/ellipse dimension drivers and equal-radius relations resolve sizes only in a derived sketch; the source curve expressions remain intact. Deleting a driver therefore restores the source expression rather than leaving a derived parameter alias behind. Unsupported relation/curve combinations fail explicitly.

Solver fingerprint `tcad-native-lm/3` replaces normal-equation LU solves with column-scaled, damped SVD steps, centered finite differences and trust-ratio acceptance. A single decomposition serves each iteration's damping trials; invalid trial geometry is rejected. Wrapped-angle discontinuities and coincident-distance cusps use a continuous/one-sided derivative branch. Convergence checks the largest individual equation, with 1e-6 mm length and 1e-8 rad angular acceptance; relative singular-value thresholds report rank, freedom and redundancy. Failure reports the largest unsatisfied sketch constraints without claiming to prove a minimal conflict set. Sketch solve/drag publish a candidate only after strict validation. Equal-radius circle groups propagate a dimension from any member, accept redundant cycles and still check conflicting dimensions. Assembly mates share the optimizer and scaled angular-axis residuals; rotation increments use an exponential map around the starting placement, avoiding Euler-coordinate gimbal singularities during solving. File placements remain ordinary Euler degrees. No constraint schema migration is needed; solver/backend fingerprints invalidate derived caches. Interactive acceptance remains with the user.

Active sketch edits enter the shared document draft immediately. Parameter edits from other presentations reconcile into that same editor; custom source bindings reconcile stable entities instead of starting a second sketch. The local solver updates the viewport sketch, and the persistent worker rebuilds downstream geometry with the existing 160 ms input debounce and stale-result rejection. Drafts retain a display-only last valid evaluation during pending or failed rebuilds; Apply continues to require the current evaluation identity. Invalid constraint intent remains in the pending document for recovery. Sketch confirmation commits the draft once; operation cancellation restores the starting session checkpoint.

JSON decoding preserves f64 round trips so a transported document retains its evaluation fingerprint. Worker durations use a protocol-compatible u64 millisecond count. Desktop UI and native file dialogs run on the platform main thread. Feature expression inputs have stable widget identities while validation diagnostics change, and edge-picking during a new chamfer or fillet uses the operation's input evaluation rather than the generated preview.

To replace an implementation, change composition code and the backend/solver fingerprint, implement the application contract, describe capability changes, and migrate references explicitly where reconstruction semantics differ. Contracts can evolve; interoperability does not mean every kernel has interchangeable topology. The initial process wire encoding and language are implementation choices rather than permanent product requirements.

This implementation has the documented limits in the root README. Compilation establishes API/type consistency, not geometric or hardware acceptance.

The version 1 `sketch_handles` contract describes point, member translation, circle radius and ellipse size/rotation goals in f64 sketch-plane coordinates. `ConstraintSolver::drag_sketch` is an optional capability with an explicit Unsupported default. The native adapter optimizes temporary cursor goals with a weak starting-position preference and strongly weighted engineering equations, then performs the normal strict constraint solve before returning geometry. Cursor goals never become persistent dimensions. Curve drivers resolve only in derived sketches, and handle edits preserve source expressions. The desktop owns capture, snapping, one history checkpoint per gesture and presentation styling; Escape restores the gesture's Session snapshot, including its preview. Persistent worker rebuilds retain the existing debounce and stale-result rejection; Apply still requires the current evaluation.

Local library references use content-pinned source snapshots and stable namespaced identities. Updates use ordinary preview transactions; rebuilding a pin requires no access to the external source. Save-as and semantic merge copy only the exact recorded resource bytes. Git comparisons materialize historical resource bytes in disposable local comparison directories without changing the checkout. Recovery writes run separately from network Git jobs so a blocked fetch cannot block recovery.

Feature-history display is an optional additive evaluation capability: `Evaluation.history` maps part/configuration mesh keys to version 1 stage descriptors and intermediate tessellations. The evaluator meshes already evaluated feature shapes during normal evaluation, caches by complete geometry source and tessellation tolerance, and records per-stage unsupported diagnostics without failing an otherwise valid final output. Stages retain the live body frontier through explicit consuming inputs, preserve independent branches/reference-only inputs, and include unconsumed sketches. Suppressed features follow the evaluator's primary-input alias; the final station uses the part's designated outputs to agree with Latest. Non-causal prefixes are unavailable. The wire encoding remains plain application-owned DTO data; shared mesh and cache ownership avoids copying history geometry on every draft/undo snapshot. No kernel object enters a stage descriptor.

The desktop history cursor is presentation state. Inspection borrows the current validated cache and leaves the complete document and worker request identity intact. Scene rendering, picking, outlines, sketch overlays and Fit consume the same stage. Navigation remains available, neighboring parts keep current geometry, and each configured instance uses its own cache. Start/edit commands restore Latest, while unsupported geometry actions expose a disabled reason. Source changes or stale/missing evaluations clear inspection; Apply still requires the normal current validated full-model evaluation. Saving/exporting/undo never use a historical display as authoritative geometry. This does not add rollback source editing or change the geometry backend fingerprint.

The native local editor uses the shared draft, a sketch-history checkpoint and current-identity worker validation; Cancel restores its starting sketch and Apply Sketch commits the outer transaction once. Evaluated sketch DTOs include the resolved sketch for display reconciliation and exports, without replacing authoritative definitions with kernel objects. Additive fields preserve schema version 1; backend/solver fingerprints invalidate prior derived caches. Interactive acceptance remains with the user.

Associative assembly evaluation resolves independent part-local geometry, applies configured leaf definitions, solves nested assemblies bottom-up, and rebuilds placement-dependent references afterwards. Geometry/placement feedback through Reference Body mate sources is rejected explicitly. Full paths disambiguate shared nested instances; MakeUnique remaps only mate endpoints reached through the affected component. Versioned drawing contracts retain associative dimensional and manufacturing annotation intent. Shared f64 paper vectors drive preview/PDF/DXF, and supported projected rational curves remain exact in standard-view DXF.
