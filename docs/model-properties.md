# Model and document properties

The Properties editor exposes manufacturing metadata for the document, a part, or an assembly. Common fields include part number, description, revision, drawing number, designer, approval, company, project, stock number, supplier, and notes. Custom keys remain unrestricted text identities within the documented bounds. These fields describe the model; engineering material, surface finish, geometry, and mass remain separate authoritative definitions.

Part and assembly values can be authored at the base definition or in a named configuration. Configuration values inherit through their parent chain, then from the base definition. The editor shows the source of each resolved value. Editing an inherited value creates a local override; removing that override restores inheritance. An explicitly empty value remains an authored blank override. Unset common fields are conveniences and do not create stored records until edited.

Assembly base properties are an additive, omitted-when-empty map, preserving unchanged legacy serialization. Configured assembly properties participate in BOM rows and model-linked drawing title blocks just like configured part properties. Document-linked title cells use document properties. These existing consumers retain their saved keys and derive their current values rather than copying stale display text.

Property keys are case-sensitive association identities. Changing a value preserves title-block and BOM associations. Selecting a key exposes the actual linked title cells and drawing BOM columns that consume it. A rename moves only the local value in the selected scope; it does not rename inherited records, other configurations, or saved consumer keys. An existing or inherited destination key is rejected rather than overwritten. Removing or renaming a key that would leave linked cells blank requires an explicit choice to retain those existing bindings after reviewing their impact. Consumers with documented model-name or configured-BOM fallbacks are disclosed. External design-table files are not scanned or rebound.

All changes use the shared validated document draft and its Apply/Cancel controls. Applying commits one undoable operation; cancellation restores the starting document. Pinned linked-component definitions remain read only until a component is made unique. Advanced Source remains available through the general source editor and uses the same validation and link-integrity guards.

The semantic contract is `cad_core::model_properties`, version 1. The desktop editor exposes independent owner/configuration controls, source indicators, property rows, value fields, impact information, and actions. Their layout and appearance remain governed by the presentation contract and user themes. No renderer objects are stored in property definitions.

A scope supports at most 4,096 entries and 8 MiB of key/value text. Keys are nonempty printable strings up to 1,024 bytes. Values support up to 64 KiB, including authored line breaks and tabs. The editor preserves keys exactly; it does not trim, normalize case, infer units, or reinterpret text as an engineering property.
